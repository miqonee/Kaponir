# Защита изображений и PDF в Community

Откройте **Настройки LLM → OCR и изображения** (`/ui/#ocr`). В новом `kaponir init` включается локальная защита. После обновления установки без `[serve.ocr]` защита выключена до явного включения. Сохранённый выбор и готовность движка отображаются отдельно.

## Установка RapidOCR

**Docker Compose.** В оба образа входят RapidOCR, ONNX Runtime и веса обоих профилей. Из папки проекта с настроенным `.env` запустите `docker compose up -d --build`. Для обработки на прокси достаточно `docker compose up -d --build kaponir`. [Подготовка Compose](WORKER.md#3-docker-compose)

**Бинарник Kaponir.** Если локальный движок недоступен, откройте **Настройки LLM → OCR и изображения** и нажмите **Установить RapidOCR**. Kaponir подготовит окружение в `KAPONIR_HOME/ocr` для прокси и управляемого локального worker. Для базовой установки нужны Python с модулем `venv` и доступ к PyPI. При выборе **Русский + английский** Kaponir скачает с ModelScope кириллическую модель и проверит её SHA-256. Если управляемое окружение уже готово, кнопка **Установить кириллическую модель** добавит только эту модель. При ошибке Web UI показывает этап установки, а подробности записывает в журнал прокси.

Оба профиля можно установить одной командой на машине прокси под пользователем службы.

```sh
kaponir ocr setup
```

Для службы с отдельным каталогом данных передайте тот же `--home`, что у `kaponir serve`. Для выбора Python используйте `kaponir ocr setup --python python3.13`. Для самостоятельно развёрнутого внешнего worker обновите Kaponir и выполните установку на его узле. Если при запуске указан `KAPONIR_OCR_PYTHON` на прокси или `KAPONIR_WORKER_PYTHON` на worker, установите зависимости в это окружение и выполните `python -I scripts/kaponir_rapidocr.py --install-cyrillic` тем же интерпретатором из каталога проекта.

## Включение и проверка

1. Выберите **Локальный OCR** и **На компьютере прокси**. Включите **Защищать изображения и PDF перед отправкой** и сохраните изменения. В состоянии движка появится **Готово · RapidOCR · PP-OCRv6 Small**.

2. Нажмите **Проверить изображение или PDF → Пример с двумя ключами → Запустить проверку**. В результате должны закрыться две области. Лаборатория использует сохранённые параметры. При выключенной защите проба работает на локальном RapidOCR. Результат показывает размеры растра у прокси, время распознавания и время всей проверки. Обработанный файл можно скачать.

3. Отправьте клиентом **Проверь конфигурацию** и приложите тот же снимок. В **Сессии → Открыть переписку** под вопросом появится карточка **Закрыто 2 области**. Откройте её, чтобы увидеть **Отправлено поставщику**. Список областей выделяет все строки выбранного значения. **Журнал запросов → Изображения** открывает результат конкретного вызова, включая вызовы с переиспользованной историей.

В **Дополнительные параметры → Маска для URL** выберите **Весь URL** или **Только совпавшая часть**. По умолчанию закрывается вся рамка URL. Частичный режим сверяет посимвольные координаты RapidOCR с видимыми границами на растре и закрывает совпавший участок. При ненадёжных границах используется полная рамка. Правила для целого чувствительного поля применяются в обоих режимах.

Если включено **Сохранять оригиналы для аудита**, нажмите на отмеченную область или её строку в списке, чтобы раскрыть этот фрагмент в просмотре изображения. Повторный клик скрывает его. Для просмотра всего исходника используйте **Показать оригинал**.

Чтобы перенести OCR на worker, выберите **Отдельный worker**, подтвердите показанный адрес и нажмите **Сохранить изменения**. В штатном запуске из бинарника `127.0.0.1:8788` обслуживает локальный worker. Прокси запустит его при проверке сохранённых настроек или при первом вложении. Очередь документов включается отдельно. В Compose адрес `http://worker:8788` уже подставляется через `KAPONIR_WORKER_URL`. Для самостоятельно развёрнутого узла задайте эту переменную или `[serve].worker_url` у прокси. Используйте HTTPS и одинаковый `KAPONIR_WORKER_TOKEN` на обоих узлах. Worker получает растр до маскирования, поэтому при смене адреса его нужно подтвердить заново.

Для **Доверенного API** выберите существующее подключение OpenAI-совместимого или Anthropic API и модель Vision. Можно ввести ID вручную. **Проверить подключение** посылает только синтетический пример и проверяет расположение двух слов. Затем подтвердите показанный URL и сохраните параметры. На этот URL уходит растр до маскирования, а к распознанному тексту применяются локальные правила. При смене URL требуется новый тест и новое подтверждение. Тип модели и каталог моделей сами по себе не подтверждают пригодность координат.

Для кириллицы выберите **Профиль распознавания → Русский + английский** и сохраните параметры. Если появится **Нужна настройка**, нажмите кнопку установки. Профиль использует детектор PP-OCRv6 Small и кириллическую модель PP-OCRv5. PP-OCRv6 читает строки на латинице и дополнительно перечитывает латинские фрагменты в смешанных строках. Прокси проверяет совпадения по обеим версиям распознавания. Профиль применяется и в Лаборатории, и к вложениям в чат, в том числе к сканам в PDF. При недоступности выбранного профиля прокси останавливает отправку вложения.

По умолчанию используется **Стандартный (PP-OCRv6)** со словарём без кириллицы. RapidOCR работает на CPU с локальными весами. Для больших кадров детектор ищет строки на уменьшенном растре, а модель чтения получает фрагменты исходного изображения. Меньшие вложения используют профиль детектора для мелкого текста. Тёплый процесс сохраняет модель между вызовами. Переменная `KAPONIR_OCR_THREADS` задаёт число потоков ONNX Runtime. По умолчанию используется до четырёх доступных CPU на процесс.

## Что проверяет прокси

- Статические PNG, JPEG, WebP и PDF, вложенные через base64 в OpenAI Chat Completions или Anthropic Messages, включая историю, вложения инструмента, выделенные маршруты `/p/{id}`, поток и Anthropic `count_tokens`. Ссылки и ID вложений дают локальную ошибку.
- В одном запросе может быть до восьми файлов и до 15 страниц PDF суммарно. По умолчанию на вложения отведено 16 МиБ. Лимит растра по умолчанию составляет 20 Мп для всех отдельных изображений суммарно и для каждой страницы PDF. На все страницы PDF в запросе отводится двойной лимит растра, по умолчанию 40 Мп. Предельный размер по стороне составляет 8192 пикселя. Параллельно выполняются два запроса с вложениями, ещё восемь могут ждать. Настройки применяются к новым запросам.
- Перед OCR изображения разворачиваются по EXIF, прозрачность сводится на белый фон. Прокси подбирает сплошной непрозрачный цвет по фону вокруг каждой области и отправляет обработанные PNG или заново собранный PDF. Если преобладающий цвет не различим, используется чёрная заливка. При распознанном чувствительном поле проверяются границы по растру. Нечёткая граница значения, непрочитанный текст на непустой странице, повреждённый файл, PDF с паролем на открытие, многокадровое изображение, недоступный движок и тайм-аут останавливают весь запрос до соединения с чат-поставщиком. Текстовые запросы идут вне очереди OCR.
- Превью и явно разрешённые оригиналы хранятся отдельно от JSON инспектора в зашифрованном Vault. Срок превью составляет семь суток, срок оригинала по умолчанию составляет сутки. Общий предел для изображений составляет 128 МиБ, действует ротация вместе с журналом запросов. Оригинал доступен отдельным запросом после явного действия в инспекторе. Для старых сессий, в которых сохранился лишь снимок входного JSON, показывается состояние **Данные об обработке изображения отсутствуют**.

Если OCR пропустил само имя поля, локальное правило по имени не сработает. Сверяйте границы на характерных для вашей работы снимках в Лаборатории. Для сложной вёрстки, наложенного текста и кадров с размытыми строками прокси может остановить отправку при неопределимых границах.

## PDF-вложения

Загрузите PDF в Лабораторию, запустите проверку и выберите страницу в списке рядом с кнопкой **Скачать обработанный PDF**. С этой же настройкой защиты прокси обрабатывает PDF, приложенные через OpenCode с моделью, которая поддерживает этот формат. В **Журнал запросов → Изображения** каждой странице соответствует своя карточка. При включённом аудите исходник страницы доступен как растр до закраски.

PDFium на компьютере прокси растрирует каждую страницу с разрешением 144 dpi. Для видимого текстового слоя PDF он также извлекает текст и координаты символов. Прокси применяет локальные правила к этому тексту и к результату OCR, чтобы проверять печатный текст, сканы и надписи в графике. Маски используют настройку для URL, а совпавшие области из двух источников объединяются. Прокси собирает новый PDF из обработанных изображений страниц по сетке растра. При пересборке удаляются текстовый слой, исходные метаданные, вложенные файлы и интерактивные элементы. Если указан системный `KAPONIR_OCR_PYTHON`, для PDF нужны `pypdfium2` и Pillow в этом окружении. В штатной установке через Web UI или `kaponir ocr setup` они уже входят в комплект.

Прокси растрирует и проверяет по одной странице PDF, затем собирает один файл из сжатых обработанных страниц. При ошибке на любой странице отправка всего запроса останавливается. На ожидание и обработку запроса с PDF отводится удвоенный тайм-аут OCR, до 60 секунд. По умолчанию это 40 секунд для PDF и 20 секунд для запросов только с изображениями.

## Воспроизведение

Установите зависимости из `scripts/requirements-worker.txt` и шрифт DejaVu Sans Mono.

```sh
cargo build --locked -p kaponir-cli
.venv-ocr/bin/python -I scripts/kaponir_rapidocr.py --install-cyrillic
.venv-ocr/bin/python scripts/test_ocr_proxy.py --binary target/debug/kaponir
```

Записывающий сервер принимает реальные HTTP-запросы от прокси. Тест сверяет сплошную заливку каждого размеченного секрета, сохранность контрольного текста, удаление метаданных и совпадение байтов PNG с инспектором. Для PDF проверяются заливка на печатной и сканированной страницах, растры в выходном файле и удаление скрытого текста и вложенного файла. Для URL сравниваются оба режима на светлом и тёмном фоне. Vision проверяется отдельным локальным сервером с заданными координатами, ошибками и задержкой.

Для браузера установите Playwright и Chromium. Запустите тестовый прокси из окружения с обоими профилями RapidOCR в одном терминале и тест во втором.

```sh
.venv-ocr/bin/python scripts/test_ocr_proxy.py --browser-fixture > /tmp/kaponir-ocr-browser.json
```

```sh
node scripts/test_ocr_browser.mjs /tmp/kaponir-ocr-browser.json target/ocr-browser
```

`PLAYWRIGHT_MODULE` можно указать для установки Playwright вне дерева репозитория, `CHROMIUM_EXECUTABLE` для системного Chromium. Тест сохраняет снимки 1366×768 в указанный каталог. Он проверяет возврат и перезагрузку вкладки, клавиатурное управление, скачивание, привязку вложений и SHA-256 превью и запроса поставщику.

С `--browser-install-fixture` тест запускает прокси с системным Python и устанавливает оба профиля RapidOCR из Web UI. Он также проверяет, что черновик настроек сохраняется. Для установки зависимостей из локальных колёс передайте `PIP_NO_INDEX=1` и путь к ним в `PIP_FIND_LINKS`. Кириллическая модель скачивается отдельно с ModelScope.

Для измерения задержки до записывающего upstream используйте оптимизированную сборку и Python с `psutil`.

```sh
cargo build --locked --release -p kaponir-cli
python3 scripts/test_ocr_proxy.py --binary target/release/kaponir --benchmark 20
```

## Результаты проверки

В сетевой выборке через записывающий upstream прошли 21 изображение. Все 32 размеченных участка со значениями полностью закрыты. Сохранён 61 публичный контрольный участок. Частично скрытых значений и лишних масок на этих публичных участках нет. Проверены оба протокола, выделенные профили, стриминг, `count_tokens`, вложения инструмента, история, EXIF, WebP, две колонки и повторы. Для JPEG контроль сохраняет допуск в девять единиц на канал из-за разницы округления декодеров.

11 запросов остановлены локально при нуле обращений к чат-поставщику. С контролируемым TSV прошли шесть прогонов, ещё два были остановлены. В опыте с одной рамкой на всю строку заливка закрыла и подпись поля согласно правилам резервного покрытия. Отключение клиента завершило дочерний процесс OCR и освободило слот. Отдельно проверена ссылка из решения детектора на область вложения. После смены правила новый вызов применил командную маску, а сохранённый PNG предыдущего вызова остался побайтно тем же. Подключение тестового удалённого worker, отказ после его остановки и обычный текстовый вызов проверены отдельно. Проверка оригиналов включала отсутствие полномочий, чужую сессию, срок хранения и очистку после перезапуска.

Прогон Chromium при 1366×768 подтвердил русский и английский интерфейсы, светлую и тёмную темы, сохранение настроек, целостность переписки после перезапуска и совпадение SHA-256 скачанного PNG, тела у upstream и превью в инспекторе.

## Исторические замеры с Tesseract

Замеры первой версии защиты. Оптимизированная сборка на базе `main` `5825187`, Tesseract 5.5.0, `rus+eng`, один поток Tesseract на изображение. Среда Linux x86-64 на AMD EPYC 9V74, 5 видимых логических CPU, квота 4 CPU и 16 ГиБ памяти. GPU не использовался. По 20 последовательных запросов на каждый режим и растр после прогрева. Время до upstream измерено от отправки клиента до чтения тела записывающим сервером на loopback. Полное время включает ответ прокси.
