## Изменения

- HTTP S1 поддерживает `protocol = "systemone"`, модель и контракт
  `state/questions → answers.candidate_N.noul`.
- Проверяются соответствие идентификаторов и числа ответов, тип `noul`, числовой диапазон.
  Сохранены ограничения раскрытия, бюджет времени, запрет редиректов и возврат к политике.
- Исправлен обнаруженный пропуск: `password: значение` в середине строки прозы теперь
  создаёт жёсткую маску. Добавлены проверки детектора и расширены сквозные тесты прокси.
- Пример настроек: [examples/route-systemone.toml](../examples/route-systemone.toml).
  Он использует `shadow = true`, L0 и бюджет S1 20 секунд. Внешний LLM upstream задаётся
  без `/v1`, модель LLM выбирается клиентом.

`harbor.infra.mycompany.example`, путь `/home/mgoloshanov/zorgbilling/k8s`,
синтетический пароль `SynTest_47!Private` в середине строки.

Локальный промежуточный HTTP-сервер перехватывал тела запросов Kaponir и пересылал их
на реальный провайдер, сохраняя потоковую передачу. Заголовки авторизации не записывались.
Проверялось отсутствие девяти исходных значений/частей в сообщениях для LLM и восстановление
в ответе. Для S1 проверялись `surface = null` и `context = null` в каждом кандидате.

SystemOne: в основном прогоне 5 успешных запросов из 7, в повторной проверке — 2 из 2.
Успешные оценки заняли 6,0–6,4 с и появились в объяснении как `s1-shadow:systemone`.
Прямой пример вопроса об urgent attention также отработал: `noul = 0.96`.
Прямые короткие запросы к Gemini с явными `stream: false` и `stream: true` вернули HTTP 200.
Без поля `stream` шлюз вернул SSE; в проверках режим задавался явно.

Первый JSON-запрос через прокси завершился HTTP 502: промежуточный сервер получил
`Connection refused` при обращении к внешнему адресу. Два запроса S1 в основном прогоне
также завершились `Connection refused`; Kaponir дождался своего бюджета 20 секунд
и продолжил с обычной политикой. Успешный повторный JSON-запрос подтверждает работоспособность
сценария, но не снимает наблюдаемую нестабильность соединения.

## Локальные проверки и границы результата

`cargo test --workspace`: **84 теста прошли**, ошибок нет. После расширения проверки
активного SystemOne и возврата к политике повторно выполнен `cargo test -p kaponir-s1`:
11 тестов прошли. `cargo build --workspace` выполнен успешно.

Тесты SystemOne проверяют порядок ответов, L0/L1/L2, ограничение credentials до L0,
неполные ответы, неверные типы и диапазон, применение оценки и сохранение маски при ошибке.
Общие проверки HTTP сохраняют проверку таймаута, размера ответа и работы из Tokio runtime.

Это функциональная проверка на одном синтетическом примере, а не измерение полноты детекторов,
качества вероятностей S1 или производительности под нагрузкой. Смысловое качество внешней модели
на L0 не оценивалось; поэтому пример конфигурации оставляет S1 в теневом режиме.
