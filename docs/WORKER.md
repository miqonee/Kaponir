# Фоновый анализ документов

[Документация](README.md) · [Команды](COMMANDS.md#worker) ·
[Discover](DISCOVERY.md) · [OCR-исследование](XIAOMI_OCR_EVALUATION.md)

Worker — отдельный процесс с постоянной очередью. Он разбирает каталог, файл или
экспорт завершённой сессии и добавляет предложения в существующую encrypted подборку
`discover`. Прокси не ждёт этого анализа при обработке запроса агента.

Это подстройка по документам: после подтверждения появляются MASK-правила и метки
для `kaponir s1 train`. Веса Xiaomi-OCR-0 не дообучаются. Автоматического создания
правил по ответам модели, захвата живого трафика и определения конца сессии нет.

## Варианты запуска

| Вариант | Что требуется | Для чего |
|---|---|---|
| Только `kaponir serve` | Бинарник | Прокси/UI без worker и загрузок OCR |
| `kaponir worker run` | Бинарник + Python 3.12+ | Разовый локальный разбор без запущенного прокси |
| `worker serve` рядом с прокси | Два отдельных процесса | Очередь, UI загрузки моделей и управление заданиями |
| Compose без профиля | Docker + Compose | Только прокси с постоянным vault |
| Compose `--profile analysis` | Docker + Compose | Прокси и worker с Python/PDF-зависимостями, volumes и лимитами |
| Worker на другом сервере | Python, бинарник, доступ к каталогу и API прокси | Разнести CPU/RAM и хранение исходников |

Нативный worker проверен на Linux x64. На macOS можно указать свой совместимый
`llama-server` через `worker.runtime`; этот вариант отдельно не проверен.
Автоустановка runtime реализована только для Linux x64. Для Windows worker
в текущей реализации используйте Linux-контейнер/WSL: блокировка очереди использует fcntl.

## 1. Минимальный CLI

Для текстовых документов OCR и дополнительные Python-пакеты не нужны:

```sh
kaponir init
kaponir worker --input-root /absolute/path/to/documents run .
kaponir discover --saved --json
```

`--input-root` задаёт разрешённый каталог; путь после `run`/`submit` указывается
относительно него. Можно передать один файл или подкаталог. Путь `.` означает весь
каталог. Предпросмотр затем доступен через `discover --saved` или веб-подборку.

Чтобы использовать изображения и PDF, подготовьте окружение:

```sh
python3 -m venv .venv-worker
.venv-worker/bin/python -m pip install -r scripts/requirements-worker.txt
export KAPONIR_WORKER_PYTHON="$PWD/.venv-worker/bin/python"
```

Понадобится Python 3.12+ с модулем venv (в Debian/Ubuntu он может быть отдельным
системным пакетом). `KAPONIR_WORKER_PYTHON` выбирает Python только для worker.
Модель и runtime загружаются отдельным заданием через запущенный worker; см. ниже.

## 2. Worker и UI на одной машине

В `KAPONIR_HOME/config.toml`:

```toml
[serve]
listen = "127.0.0.1:8787"
worker_url = "http://127.0.0.1:8788"

[worker]
listen = "127.0.0.1:8788"
input_root = "/absolute/path/to/documents"
model_dir = "models"
data_dir = "worker"
model = "q4"
threads = 2
max_files = 1000
max_file_bytes = 16777216
max_pages = 100
max_edge = 1024
ocr_timeout_seconds = 300
# runtime = "/absolute/path/to/llama-server"
```

Относительные пути `input_root`, `model_dir`, `data_dir` считаются от KAPONIR_HOME.
По умолчанию input_root — `KAPONIR_HOME/inbox`; создайте каталог и положите туда файлы.

В двух терминалах:

```sh
kaponir worker serve
kaponir serve
```

Можно указать адрес worker через `KAPONIR_WORKER_URL` у прокси вместо config.toml.
В панели откройте **Настройки → Фоновый анализ документов**:

1. Выберите Q4/Q5 и нажмите «Скачать модель».
2. Дождитесь завершения задания загрузки.
3. Укажите каталог/файл внутри показанного input_root.
4. Нажмите «Поставить в очередь».
5. После обработки откройте предложения и нажмите «Открыть подборку».

Эквивалентные CLI-команды (обращаются к worker, а не запускают второй обработчик):

```sh
kaponir worker download q4
kaponir worker submit contracts
kaponir worker status
kaponir worker pause JOB_ID
kaponir worker resume JOB_ID
kaponir worker cancel JOB_ID
```

`worker run` требует свободной очереди без другого процесса-worker; если сервис уже
запущен, используйте `submit`. После задания run завершается. В обоих вариантах
кандидаты сохраняются в том же vault, имена документов стабильны при повторе.

## 3. Docker Compose

Из корня репозитория:

```sh
cp deploy/compose.env.example .env
# Задайте два разных длинных токена и каталог исходников в .env.
# Пример генерации каждого токена: openssl rand -hex 32
mkdir -p documents

# Только прокси:
docker compose up -d --build kaponir

# Прокси и отдельный worker:
docker compose --profile analysis up -d --build
```

UI — `http://127.0.0.1:8787/ui/`; для входа нужен KAPONIR_API_TOKEN из .env.
Без профиля analysis достаточно этого токена. Worker требует отдельный
KAPONIR_WORKER_TOKEN при старте на контейнерном non-loopback адресе.
Открытый наружу адрес worker не публикуется. Прокси связывается с ним по внутренней
сети с отдельным KAPONIR_WORKER_TOKEN. Для доступности UI извне настройте обычный
reverse proxy/TLS; опубликованный порт по умолчанию привязан к localhost.

Volumes:

- `kaponir-data`: vault, ключи, настройки, правила, очередь и её checkpoints;
- `kaponir-models`: веса и runtime, переживают пересоздание контейнера;
- `KAPONIR_INPUT_DIR:/inputs:ro`: исходники на Docker-host, только чтение.

Worker по умолчанию ограничен **2 CPU и 2560 MB памяти**, proxy — 1 GB.
Xiaomi стартует только для изображений/сканов и выгружается в конце задания.
GPU не требуется; текущий автоматический runtime CPU-only.

```sh
docker compose logs --tail=100 worker
docker compose stop worker          # останавливает обработчик, очередь остаётся
docker compose --profile analysis up -d worker
docker compose down                # volumes остаются
```

`down -v` удаляет именованные volumes вместе с ключами/vault/очередью/моделью.
Это не команда обычного обновления.

По умолчанию Dockerfile собирает бинарник из исходников (`KAPONIR_BUILD=source`).
Есть быстрый локальный вариант для уже собранного Linux-бинарника той же архитектуры:

```sh
cargo build --locked --release -p kaponir-cli
KAPONIR_BUILD=prebuilt docker compose --profile analysis up -d --build
```

Нельзя копировать в Linux-образ macOS/Windows-бинарник. Dockerfile имеет отдельные
цели `proxy` (без Python/OCR-зависимостей) и `worker` (Python, Pillow, pypdfium2).
В Docker-контекст не включаются реальные ключи, документы, .env и GGUF-веса.
При первом старте entrypoint создаёт новый KAPONIR_HOME, если vault.key отсутствует.

## 4. Worker на другом сервере

Worker должен видеть свой каталог документов; UI всегда показывает путь на машине
worker, а не на компьютере с браузером. Для отдельного vault на сервере прокси:

```toml
[worker]
listen = "0.0.0.0:8788"
input_root = "/data/documents"
api_url = "https://kaponir.internal"
```

- На worker задайте `KAPONIR_WORKER_TOKEN` и `KAPONIR_API_TOKEN` для записи
  кандидатов через API прокси. Его runtime и очередь остаются на worker-сервере.
- На прокси задайте `KAPONIR_WORKER_URL` и тот же `KAPONIR_WORKER_TOKEN`.
- Для межсерверного HTTP используйте доверенную сеть или TLS reverse proxy.
- Без api_url локальный worker запускает CLI для записи в собственный KAPONIR_HOME.
  В Compose используется общий volume; транзакции SQLite защищают объединение
  подборки от одновременных записей CLI и Web.

Non-loopback bind worker требует токен. Управляющие методы проверяют токен,
Content-Type и Origin. Прокси проверяет свою обычную авторизацию до обращения к worker.

## Файлы и управление заданиями

Поддерживаются UTF-8 txt/md/json/jsonl/log/yaml/yml/toml/ini/env/csv, изображения
PNG/JPEG/WebP/BMP/TIFF и PDF. Из PDF сначала извлекается текстовый слой; OCR
включается для страницы без текста. Многостраничные PDF/TIFF обходятся постранично.
JSON-экспорт сессии анализируется как текстовый документ; отдельного парсера
форматов всех агентов и автоматической записи текущих сессий нет.

Исходники не копируются в очередь. SQLite worker содержит пути, размеры/mtime,
состояния и checkpoints, без распознанного текста. Каталог очереди создаётся с
правами 0700. Кандидаты/маскированные примеры хранятся в encrypted vault Kaponir.
Для импорта через CLI извлечённый текст кратковременно существует в закрытом
временном каталоге worker и удаляется после импорта. Лог raw-ответов OCR не ведётся.

- Один consumer на очередь; второй процесс получает ошибку блокировки.
- Возобновление — с файла/страницы. Незавершённая единица может обработаться ещё раз;
  stable document name + discover dedup предотвращают повторное увеличение счётчиков.
- При паузе/отмене собственный OCR-процесс останавливается. Импорт кандидатов,
  который уже начался, может завершиться; собранные кандидаты сохраняются.
- После аварийного завершения running-задание возвращается в очередь при старте.
- При изменении исходного файла после построения manifest он отмечается ошибкой.
  При изменении input_root нужно подать новое задание.
- Ошибка одного файла не мешает обработке остальных, итоговый статус будет failed.
  Уже полученные кандидаты сохраняются; исправленный каталог можно подать заново.
- Symlink не обходятся, абсолютные пути и выход за input_root отклоняются.
  Это ограничение области анализа, не изоляция от администратора самого worker-хоста.
- В очереди до 1000 записей; при заполнении удаляется старейшая завершённая запись,
  кандидаты не удаляются. Одновременно до 1000 незавершённых заданий. UI показывает
  последние 200 записей.
- Лимиты discover (2 МиБ текста, 256 кандидатов за один анализ и др.) сохраняются.
  Если часть кандидатов усечена, файл отмечается ошибкой с предложением разделить его.

## Модель и обучение

Встроенный downloader знает только две фиксированные версии: Q4_K_M (~737 MB
вместе с визуальным модулем) и Q5_K_M (~785 MB). Веса взяты из community-пакета
prithivMLmods/Xiaomi-OCR-0-GGUF, runtime — llama.cpp b12038 Linux x64. SHA-256
проверяются перед установкой; несовпадение не заменяет рабочий файл. Готовые файлы
проверяются и повторно не скачиваются. На другой ОС/архитектуре задайте свой runtime.

Pillow/pypdfium2 не скачиваются кнопкой модели: для native CLI они устанавливаются
в выбранный Python отдельно, в Compose worker уже входят в образ. После паузы
загрузки незавершённый файл скачивается заново; уже проверенные файлы используются.

Worker запрашивает OCR-текст, а не доверяет модели финальное решение mask/keep:
проверка Q4/Q5 показала, что
OCR полезен, а такая классификация нестабильна. Дополнительный S1 включается явно
через checkbox/`submit --s1` и использует настройки раскрытия основного пространства.
Он тоже не создаёт правила автоматически. Подтверждения пользователя используются
при следующем ручном `kaponir s1 train`, веса Xiaomi от этого не меняются.

## Конфигурация и обновление

`[worker]` и `[serve].worker_url` входят в общий экспорт/импорт настроек CLI/Web.
Токены из переменных окружения не экспортируются. Файлы весов, runtime, очередь,
источники и обучающие данные vault не входят в JSON настроек: это отдельные volumes/
резервные копии. После изменения config.toml перезапустите worker; после изменения
worker_url перезапустите proxy. Compose-переменные окружения имеют приоритет над
соответствующими параметрами файла.

Для обновления остановите worker, сохраните volumes и исходники, обновите образ/
бинарник и запустите снова. Не удаляйте vault.key отдельно от vault.db.
