# Панель управления

[Документация](README.md) · [Быстрый старт](../README.ru.md#3-откройте-web-ui) ·
[Справочник CLI](COMMANDS.md) · [Безопасность](SECURITY.md)

Главный экран — обзор реального трафика прокси. Ручная проверка каждого запроса не нужна:
клиент обращается к API Kaponir, прокси маскирует текст перед отправкой провайдеру и
восстанавливает значения в ответе. Вкладка «Поставщики и API» позволяет подключить поставщика и получить параметры клиента.

## Поведение по умолчанию

Kaponir маскирует поддерживаемые текстовые поля перед отправкой и восстанавливает
значения в ответах. Для подключения достаточно изменить адрес API и ключ доступа;
специальный заголовок сессии не требуется. Прокси не добавляет инструкций модели и
не повторяет запросы после ошибок по умолчанию. Выбор модели, параметры генерации,
схемы инструментов и идентификаторы агента остаются под управлением клиента.

Подсказка о плейсхолдерах доступна отдельно через `[serve] system_hint = true`.
Новые конфигурации создаются с `false`. Существующие конфигурации с явно заданным
`true` сохраняют прежнее поведение; для отключения измените значение и перезапустите сервер.
Маскирование само по себе меняет видимый модели текст; это не гарантия неизменности ответа.
При работе с сохранёнными ключами прокси подставляет учётные данные поставщика и убирает
клиентские cookies, OpenAI organization/project, чтобы не переносить их между аккаунтами.
Если интеграция зависит от этих полей или серверного состояния, её совместимость нужно
проверять отдельно; отдельный адрес закрепляет выбор подключения.

## Навигация

- **Обзор**: запросы, замены по категориям, восстановление, ошибки, активность и последние события.
- **Поставщики и API**: адрес, зашифрованный ключ, проверка моделей, endpoint Kaponir и примеры SDK.
- **События**: до 200 завершённых запросов, фильтр проблем, код HTTP, длительность и счётчики.
- **Правила**: существующие контуры и редактор правил.
- **Разбор решений**: уточнение спорных значений без остановки автоматической работы.
- **Лаборатория**: маскирование, восстановление, объяснения и выделение текста.
  Нужна для проверки детекторов или ручного обмена текстом с чат-ботом в браузере.
- **Настройки**: состояние S1, защита API-токеном, настройка профиля, анализ документов и диагностика.

RU/EN выбирается по браузеру и переключателем. Черновики не отправляются в localStorage:
там хранится только язык. Переключение языка не перезагружает страницу и сохраняет ввод.
Переводы и правила участия: [CONTRIBUTING.md](../CONTRIBUTING.md).

## Статистика

`/api/v1/metrics` сохраняет технические поля `engine`, `http`, `stream_errors` и добавляет
`traffic`. Обзор использует **только `traffic`**:

- учитываются `/v1/messages`, `/v1/messages/count_tokens`, `/v1/chat/completions`;
- лаборатория, `discover`, sidecar REST, просмотр моделей и метрик не учитываются;
- повторная отправка блока из кэша учитывает его замены повторно;
- событие фиксируется при завершении ответа или прерывании потока; текущие запросы — `in_flight`;
- длительность включает ожидание провайдера и обработку всего потока; это не только накладные
  расходы маскирования. p95 относится к доступным последним событиям выбранного периода;
- `errors` включает HTTP 4xx/5xx, ошибки чтения потока и восстановления; отменённые клиентом
  запросы считаются отдельно. `blocked` означает отсутствие попытки пересылки;
- `sent=true` означает попытку пересылки, а не доказанное получение документа провайдером;
- категории берутся из категории принятой маски, а не угадываются по тексту или названию токена;
- число замен — вхождения, не число уникальных секретов и не оценка полноты обнаружения.

Хранятся до 168 часовых корзин и 200 событий, а также суммарные счётчики с запуска процесса.
Периоды соответствуют часовым корзинам; семидневный график объединяет их по 24 часа.
История обезличена и находится **в памяти**: сохраняется при обновлении правил и теряется при
перезапуске. Это не долговременный журнал аудита. Prometheus по-прежнему экспортирует технические
счётчики; запись долговременной истории запросов требует отдельного этапа.

События содержат только локальный последовательный id, фиксированное имя протокола,
время, исход, HTTP-статус и числовые показатели. В них нет сообщений, оригиналов, токенов,
имён моделей и идентификаторов сессий. Доступ к `/api/v1/metrics` защищён API-токеном.

## Необязательная адаптация

В Web: «Настройки → Первоначальная настройка» либо карточка на обзоре.
Три шага: способ использования, корпоративные домены / конфиденциальные проекты, проверка.
Можно пропустить. Режим использования выбирает инструкции; не выключает другие инструменты.
Домены вводятся без схемы, пути или порта; для IDN используется punycode.
Проекты — по одному на строку; выбирайте только конфиденциальные названия.

В CLI:

```sh
kaponir init --wizard --language ru
kaponir init --wizard --language en
```

Без `--wizard` вопросов нет. Отказ и EOF не применяют профиль; создание базового home самим
`init` сохраняется. Перед записью есть отдельное подтверждение. CLI и Web используют общий
валидатор `kaponir_core::onboarding::plan`. Web endpoint: `POST /api/v1/ui/setup` с массивами
`domains`, `projects` и `apply=false` для предпросмотра / `apply=true` для записи.

Добавляются только личные MASK-правила и корпоративные домены; существующие настройки и
правила сохраняются. Повторный запуск с теми же ответами не дублирует новые правила.
Внешний S1 не подключается и не вызывается. Это настройка правил, не обучение модели.
Обучение локального S1 остаётся отдельной командой `kaponir s1 train`.

## Поставщики и ключи

В панели можно хранить до 64 именованных подключений, каждое со своим зашифрованным ключом.
Выберите формат OpenAI-compatible или Anthropic, нажмите «Добавить ключ» и укажите название,
адрес поставщика и ключ. Если уже выбрано подключение, новая форма предлагает его адрес
и список моделей; ключ не копируется. OpenAI, OpenRouter и DeepSeek имеют готовые адреса.
Произвольные совместимые сервисы и агрегаторы поддерживаются через «Свой поставщик».

Доступны два режима:

- **Только отдельный адрес**: для OpenAI SDK — `/p/{id}/v1`, для Anthropic SDK — `/p/{id}`.
  Этот адрес всегда использует выбранное подключение, независимо от остальных ключей.
- **Общий и отдельный адрес**: ключ также участвует в общем `/v1/chat/completions` или
  `/v1/messages`. По полю `model` выбираются включённые подключения с этой моделью;
  запросы одной сессии, модели и формата API закрепляются за одним подключением.
  Новые сессии распределяются по ключам стабильным хешированием. Привязка проверяется
  при каждом запросе: отключённый, удалённый или больше не поддерживающий модель ключ
  заменяется подходящим.

Для собственной интеграции можно необязательно передавать `X-Kaponir-Session` с уникальным
ID диалога, постоянным между ходами. Это внутренняя метка привязки Kaponir, а не замена
сессии агента; она не передаётся поставщику. В стандартных примерах заголовка нет.
Без него используется хеш первого сообщения,
не являющегося system/developer: одинаковые начала диалогов имеют одну привязку.
Сжатие или обрезка истории может изменить первое сообщение и привязку. Для строгого
закрепления без настройки агента используйте отдельный адрес подключения.
Хранятся до 8192 привязок в памяти; вытесняется наименее недавно использованная.
Срок простоя задаётся `session_idle_hours`. При перезапуске, истечении срока или вытеснении
первоначальный выбор вычисляется заново; изменения привязки после 429 не сохраняются на диск.
Закрепление помогает повторно использовать prompt cache, но его наличие и срок жизни
определяются поставщиком; при смене ключа кэш может потребовать прогрева.

По умолчанию HTTP 429 возвращается клиенту без повтора, даже при нескольких ключах в пуле.
Переключение включается явно опцией «Переключать ключ при HTTP 429» (`retry_on_429` в API)
у исходного и резервного подключения. Она выключена также у ранее сохранённых подключений,
в которых этого поля ещё нет. В этом режиме общий адрес повторяет те же замаскированные
байты с другим включённым ключом для той же модели и того же адреса API (`base_url`),
сохраняя новую привязку для следующих ходов. Совпадение адреса не гарантирует общность
аккаунтов: включайте опцию только для взаимозаменяемых ключей и запросов с полной историей.
Для серверных разговоров, файлов или другого состояния, связанного с аккаунтом,
переключение следует оставить выключенным. В рамках одного
запроса каждый ключ пробуется не более одного раза (максимум 64 попытки). Если все
подходящие ключи вернули 429, клиент получает последний ответ, включая `Retry-After`.
Ожидания и общего карантина ключей нет: другие сессии могут получить свой 429 и переключиться.
Прочие HTTP-ошибки, сетевые сбои и уже начатые ответы/SSE не запускают повтор.
Отдельный адрес не переключается на другой ключ даже при 429.
Балансы и квоты поставщиков остаются отдельными. По умолчанию новый ключ используется
только через отдельный адрес. Добавление ключа в общий пул — явная настройка.

### Модели и проверка

«Получать модели автоматически» включён по умолчанию. При сохранении подключения прокси
запрашивает у поставщика `GET /v1/models`, сохраняет найденные ID и сразу обновляет общий
каталог. При использовании общего или отдельного адреса каталог обновляется не чаще одного
раза в пять минут. В UI видны время последнего обновления и ошибка, если обновление не удалось;
последний успешный список остаётся доступным. Ключ и ответы модели в панель не возвращаются.

Поддержана пагинация через `after_id` и `last_id`: максимум 20 страниц, 1000 моделей и 2 МиБ
ответа. При некорректном курсоре каталог помечается ошибкой и не заменяется неполным списком.
Если поставщик не поддерживает discovery, снимите автоматический режим и укажите модели вручную,
по одному ID на строку. Кнопка проверки остаётся для немедленного обновления до сохранения.

Общий `GET /v1/models` объединяет **сохранённые** списки включённых подключений общего пула,
убирает дубликаты и исключает изолированные/отключённые ключи. Каталог не является онлайн-проверкой
доступности или квоты. Кнопки моделей в панели подставляют ID в пример SDK; реальную модель
каждого запроса выбирает клиент. Отдельный `/p/{id}/v1/models` проксирует список выбранного
поставщика (включая его параметры пагинации). Каталоги разных форматов API не смешиваются:
для общего Anthropic-каталога передайте `anthropic-version`, как это делает SDK.

При обновлении прежние одиночные профили сохраняют свои ключи, адреса и общий endpoint.
У них есть режим «Все модели — совместимость с прежней настройкой», который сохраняет
маршрутизацию без фильтра ID. Один такой профиль без списка моделей использует прежнее live
discovery; в многоключевом каталоге видны только явно сохранённые ID. После проверки моделей
панель предлагает перейти к явному списку. Прежние профили получают стабильные ID `openai`
и `anthropic`; новые — случайный ID, независимый от названия и ключа.

### Сохранение, отключение и удаление

«Сохранить подключение» применяет изменения к новым запросам без перезапуска. Уже начатые
запросы завершаются с прежними настройками. Переключатель «Подключение включено» временно
исключает ключ из общего пула и блокирует его отдельный адрес. Удаление подтверждается
в самой форме. После удаления отдельный адрес отвечает 404, после отключения — 503.
Если для модели нет подходящих ключей в управляемом общем пуле, запрос останавливается
с 503; он не отправляется незаметно поставщику из конфигурации.

Зашифрованный реестр хранится в `meta` vault под ключом `providers:v2`. Первая запись
переносит старые профили в реестр; пустой реестр не восстанавливает удалённые профили.
Изменения защищены общей блокировкой vault в процессе, поэтому параллельное добавление
ключей не теряет другие подключения. API возвращает настройки и `key_saved`, но не секрет.
Пустое поле ключа сохраняет прежний ключ только при неизменном нормализованном адресе
**того же подключения**. При смене адреса нужно ввести ключ заново.

Ключи шифруются ChaCha20-Poly1305 существующим master key vault; браузерное хранилище их
не содержит. Поле очищается после сохранения. Профили переживают перезапуск и восстанавливаются
из резервной копии vault вместе с master key. Удаление исключает ключ из активного реестра;
это не отзыв ключа у поставщика и не обещание физического стирания из старых резервных копий.
Допускается HTTPS и HTTP на loopback, редиректы отключены. Тела ошибок проверки поставщика
не возвращаются в панель, поскольку могут содержать секреты.

Сохранённые подключения имеют приоритет над `serve.*_upstream` и CLI-параметрами для
управляемого формата. Форматы, для которых подключения ещё никогда не добавлялись, сохраняют
прежний режим: адрес из конфигурации, ключ передаёт клиент. Для конфигурационного
`*_upstream` по-прежнему нужен адрес без конечного `/v1`; форма принимает оба варианта.

### Доступ, события и API

Все endpoints используют общий токен Kaponir (`serve.api_token`), если он задан:
`Authorization: Bearer` или `x-kaponir-token` для прокси. В примере Anthropic используется
`auth_token`, а в запрос поставщику подставляется его `x-api-key`. Без токена локальный SDK
может использовать фиктивное значение `kaponir-local`. Токен Kaponir не уходит поставщику.
Отдельный endpoint выбирает ключ, но не создаёт отдельную роль или границу доступа клиента.

События прокси включают безопасный `connection_id`, чтобы различать подключения.
Названия подключений и ключи в историю трафика не попадают.

- `GET /api/v1/connections` — список подключений и управляемых форматов.
- `POST /api/v1/connections` — создать подключение.
- `PUT /api/v1/connections/{id}` — обновить подключение; формат API неизменяем.
- `DELETE /api/v1/connections/{id}` — удалить подключение.
- `POST /api/v1/connections/test` — проверить черновик, при редактировании передать `id`.

JSON создания/обновления: `kind`, `name`, `base_url`, `api_key`, `enabled`, `pool`, `models`.
Поле `all_models` предназначено для явного режима без фильтра (в UI — совместимость старых
профилей). `pool` по умолчанию выключен. Пустой список без `all_models` недопустим для общего пула.
Старые `/api/v1/providers*` сохранены для совместимости; новые клиенты должны использовать
`/api/v1/connections*`.
