# Панель управления

[Документация](README.md) · [Быстрый старт](../README.ru.md#3-откройте-web-ui) ·
[Справочник CLI](COMMANDS.md) · [Безопасность](SECURITY.md)

На обзоре доступны проверка текста, подключение клиента, поиск в документах, последнее задание и трафик прокси. Клиент отправляет запросы на адрес Kaponir. Прокси маскирует значения перед отправкой поставщику и восстанавливает их в ответе. Подключения находятся в разделе **Настройки прокси → Поставщики API**.

## Поведение по умолчанию

Kaponir маскирует поддерживаемые текстовые поля перед отправкой и восстанавливает
значения в ответах. Для подключения достаточно изменить адрес API и ключ доступа;
специальный заголовок сессии не требуется. Прокси не добавляет инструкций модели и
не повторяет запросы после ошибок по умолчанию. Выбор модели, параметры генерации,
схемы инструментов и идентификаторы агента остаются под управлением клиента.

Подсказка о плейсхолдерах доступна отдельно через `[serve] system_hint = true`.
Новые конфигурации создаются с `false`. Существующие конфигурации с явно заданным
`true` сохраняют прежнее поведение; для отключения измените значение и перезапустите сервер.
Маскирование само по себе меняет видимый модели текст; это не гарантия неизменности ответа.
При работе с сохранёнными ключами прокси подставляет учётные данные поставщика и убирает
клиентские cookies, OpenAI organization/project, чтобы не переносить их между аккаунтами.
Если интеграция зависит от этих полей или серверного состояния, её совместимость нужно
проверять отдельно; отдельный адрес закрепляет выбор подключения.

## Навигация

Язык и тема находятся внизу бокового меню. На телефоне меню открывает кнопка в левом верхнем углу. В шапке видно название открытого экрана и состояние заданий.

| Раздел | Как им пользоваться |
|---|---|
| **Обзор** | Счётчик «Открыть на проверку» ведёт к ожидающим находкам. Рядом доступны проверка текста, поиск в документе и текущее задание с количеством обработанных значений. В последних сессиях видны реальные запросы прокси. Откройте запрос для просмотра замен, оснований и связанных находок. |
| **Сессии** | «Переписка» справа открывает сообщения. На компьютере слева видны время и состояние каждого запроса в этой сессии. Выберите запрос мышью или стрелками на клавиатуре. В режиме «Запросы» под каждой сессией видны её запросы. «Требуют внимания» показывает число затронутых запросов. Нажмите на счётчик, чтобы увидеть причины и подробности. |
| **Находки** | Поиск по значению и контексту доступен сразу. Нажмите на значение для предпросмотра с подсветкой. Стрелки рядом с номером находки переключают фрагменты по всей текущей выборке. Чекбокс отмечает значение и открывает панель действий внизу. «Предложения ИИ» показывает готовые решения о маскировании. Нажмите на значение, прочтите предлагаемое действие и примите или отклоните его. Отклонённое предложение оставляет находку на ручной проверке. «В датасет все N» доступно без предварительного выбора. |
| **Лаборатория** | Выберите «Проверка текста» для предпросмотра замен или «Найти значения» для поиска в тексте, файле и сессиях. «К находкам» возвращает к списку с прежними фильтрами. Нажмите «Сохранить и копировать» или Ctrl+Enter. Панель подтвердит сохранение токенов и откроет переход к восстановлению. |
| **Датасет** | «Начать проверку» открывает первый черновик текущей выборки. Щёлкните по подсвеченному вхождению, чтобы изменить его тип или решение. «Сохранить и продолжить проверку» переводит к следующему черновику. После последнего примера открывается список проверенных с выгрузкой для обучения. |
| **Правила** | Найдите правило по значению, типу или заметке. Фильтр области отделяет личные, командные и корпоративные правила. Здесь же открываются создание правила, аудит и мастер первоначальной настройки. |
| **Настройки LLM** | «Модель и ресурсы» задаёт общую модель и параллельность. «Обнаружение» настраивает поиск значений, «Категоризация» определяет их тип и область. В «Служба и очередь» доступны установка моделей, управление обработкой и журнал. |
| **Настройки прокси** | Подключите поставщика API, настройте доступ, импортируйте конфигурацию или откройте диагностику. |
| **Задания** в шапке | Откройте меню, чтобы увидеть активный запрос или документ, этап обработки и очередь. «Все задания» группирует активные работы, ожидающие и историю. В карточке запроса доступна исходная переписка. После запуска проверки её постоянная страница открывается автоматически. |

Чекбокс над списком выбирает видимую страницу. Команда **Выбрать все N по фильтру** фиксирует текущий состав выборки, включая следующие страницы. При открытии задания можно вернуться к выбранной странице и выделению. Сбор черновиков доступен и при остановленной модели. Снимки выборок, история ручных проверок и квитанции добавления хранятся 30 дней. Срок их хранения не ограничивает хранение самих примеров датасета.

В карточке находки отдельно показаны источник, тип и решение. Проверка типа или оценка детектора сами по себе не создают предложение ИИ. «Получить предложение ИИ» запускает пересмотр. «Решить вручную» позволяет выбрать действие, тип и область правила. Вкладка «Происхождение» содержит оценки, модели и ссылки на исходный запрос и задание.

У кнопки запуска выберите способ проверки. A определяет тип и действие, B дополнительно учитывает политику приватности, C проверяет конкретное вхождение, D объясняет решение по этому вхождению. История сохраняет использованную модель, подключение и сценарий. Рекомендацию применяют отдельно после просмотра изменений.

Рядом с выбором сценария показаны рекомендация для модели, число верных решений и время проверки 32 значений на стенде. В таблице «Сравнить A–D для модели» видно, сколько из 16 приватных значений модель скрыла и сколько из 16 публичных сохранила. Число полученных ответов помогает отличить ошибку решения от пропущенного ответа. Прочерк означает, что для этого профиля замера нет. «Среднее по стенду» сравнивает восемь моделей на одних и тех же значениях. Это время проверки готовых находок. Поиск в исходном документе и скорость вашего ПК измеряются отдельно. [Протокол замера](experiments/NATIVE_MODEL_RETEST.md)

В «Заданиях» фоновый анализ показывает подготовку текста, поиск по фрагментам, категоризацию найденных значений и сохранение. Счётчик относится к текущему этапу. Если все обработчики заняты, очередь показывает действующий лимит одновременных заданий. Кнопка «Настройки параллельности» в ожидающем задании открывает соответствующее поле. Если большой фрагмент приходится делить, общее число фрагментов увеличивается. Пересмотр находок показывает число обработанных значений из принятой выборки. Время обновления очереди отражает успешный опрос сервера, а в карточке отдельно указано время последнего изменения самого задания.

Поиск из переписки запускает локальные детекторы. Результат показывает, какая сессия проверена и что в ней найдено. «Открыть находки этого поиска» ведёт к этой выборке. Там можно скрыть значения вручную, добавить их в датасет или отправить модели. Прогресс проверки моделью виден в «Заданиях».

При выборе локальной модели с четырьмя полными замерами можно выбрать скорость, обнаружение приватных значений или сохранение публичных. Панель подставит сценарий и покажет измеренный результат. Выбор вступит в силу после сохранения или запуска конкретной проверки. Для профилей с неполными данными доступны ручной выбор и таблица замеров.

В настройках производительности видны показатели, переданные воркером. Лимиты контейнера и дополнительные показатели раскрываются по запросу. Для загруженной модели можно запустить замер на синтетическом тексте в свободное время службы. Панель показывает измеренную пропускную способность и предлагает применить подходящее число параллельных запросов. Настройка действует для следующих заданий.

Русский и английский интерфейсы, светлая и тёмная темы переключаются без перезагрузки. Прежние прямые ссылки на лабораторию, просмотр сессий и настройки модели доступны в новой навигации.

## Статистика и сессии

`GET /api/v1/metrics` сохраняет технические поля `engine`, `http`, `stream_errors` и `traffic`.
Дашборд использует только `traffic`: лаборатория, документы и sidecar REST не учитываются.

Один входящий HTTP-запрос создаёт одну запись, включая все чанки SSE и повторные попытки
после 429. Выполняющиеся запросы находятся в `traffic.active`, завершённые — в `traffic.events`.
Завершение, прерывание и ошибка потока фиксируются однократно. `count_tokens` отмечается отдельно.

Сессия определяется по `X-Kaponir-Session`, иначе по первому сообщению не от system/developer.
В списке сохраняются непрозрачный `session_id` и `session_source=explicit|inferred`, а не исходный
заголовок или текст. Автоматическая группировка приблизительная: одинаковые начала могут совпасть,
обрезка истории может изменить связь. Старые события без метаданных остаются отдельными запросами.

Новые замены и повторные подстановки из кэша истории считаются отдельно. Категории относятся к новым
заменам; это вхождения, а не уникальные сущности и не измерение полноты защиты. Счётчики токенов
внутри одного SSE-запроса учитываются как накопительные, а не суммируются на каждом чанке.

Часовые счётчики за 168 часов и суммарные показатели сохраняются в зашифрованном Vault независимо
от последних 200 подробных событий. Перезапуск восстанавливает их без повторного учёта.
При первом обновлении доступна только сохранённая ранее история; недостающие старые данные
не восстанавливаются из предположений.

Время Kaponir включает маскирование, классификатор и восстановление конкретного запроса.
Ожидание поставщика показывается отдельно. p50/p95 рассчитываются по суммарным временам запросов
в доступной выборке; её размер указан. Перцентили отдельных операций не складываются.
При отсутствии измерений показывается «—».

Ответы метрик и списка событий содержат метаданные без исходных сообщений, оригиналов замен
и полных ошибок поставщика. `GET /api/v1/ui/events/{id}` возвращает подробный инспектор,
защищённый теми же проверками доступа. Его содержимое сохраняется зашифрованным.
У событий старых версий без связей с журналом интерфейс прямо сообщает, что конкретные
находки восстановить нельзя. Исторические счётчики не пересчитываются после решения человека.

Чтобы скрывать одно значение без модели, откройте его фрагмент, нажмите **Решить вручную**, выберите **Скрывать значение** и проверьте тип и область. Для нескольких находок отметьте строки или всю выборку и нажмите **Создать правила маскирования**. Оба способа работают с отключёнными моделями.

Для находки детектора **Создать исключение** применяет KEEP к будущим запросам. **Закрыть без правила** переносит запись в историю. Для находки фонового поиска **Отклонить находку** сохраняет отрицательную метку. **Отклонить предложение** действует только на конкретный ответ модели и оставляет находку на проверке. Из истории можно вернуть закрытую запись или отменить созданное правило.

## Точность и исправление накопленных ошибок

Неизвестное слово или неизвестный публичный домен без дополнительных оснований сами по себе
не создают маску. Подтверждённые правила, корпоративные домены, секреты и структурно подтверждённые
внутренние данные продолжают защищаться. Обычные слова и публичные ID моделей не предлагаются
как проекты без иных оснований. Короткие IPv6 требуют адресного контекста и границ вне идентификаторов.

Отключённое правило не участвует в детекции, словарях, профиле S1 и обучении. Соответствующее точное
значение исключается из памяти/кэша маскирования сессий, включая повторное обучение при восстановлении.
Записи токенов не удаляются: старые ответы по-прежнему восстанавливаются. Включённый встроенный
детектор настоящего секрета может продолжить защищать его независимо от отключённого правила.

Аудит также показывает подозрительные значения из старой памяти сессий, даже без отдельного правила.
Выбранные исключения хранятся зашифрованными и переживают перезапуск, не блокируя подтверждённые
правила или встроенные детекторы реальных секретов. `PUT /api/v1/ui/rules/audit/memory` принимает
`ids`, `revision`, `disabled`; восстановление снимает исключение автоматической памяти.

API аудита: `GET /api/v1/ui/rules/audit`; `PUT` принимает `scope`, `indices` (либо прежний одиночный
`index`), `revision`, `disabled`. Устаревшая версия возвращает HTTP 409.

## Необязательная адаптация

Откройте **Правила → Мастер настройки правил**.
Три шага: способ использования, корпоративные домены / конфиденциальные проекты, проверка.
Можно пропустить. Режим использования выбирает инструкции; не выключает другие инструменты.
Домены вводятся без схемы, пути или порта; для IDN используется punycode.
Проекты — по одному на строку; выбирайте только конфиденциальные названия.

В CLI:

```sh
kaponir init --wizard --language ru
kaponir init --wizard --language en
```

Без `--wizard` вопросов нет. Отказ и EOF не применяют профиль; создание базового home самим
`init` сохраняется. Перед записью есть отдельное подтверждение. CLI и Web используют общий
валидатор `kaponir_core::onboarding::plan`. Web endpoint: `POST /api/v1/ui/setup` с массивами
`domains`, `projects` и `apply=false` для предпросмотра / `apply=true` для записи.

Добавляются только личные MASK-правила и корпоративные домены; существующие настройки и
правила сохраняются. Повторный запуск с теми же ответами не дублирует новые правила.
Внешний S1 не подключается и не вызывается. Это настройка правил, не обучение модели.
Обучение локального S1 остаётся отдельной командой `kaponir s1 train`.

## Поставщики и ключи

В панели можно хранить до 64 именованных подключений, каждое со своим зашифрованным ключом.
Выберите формат OpenAI-compatible или Anthropic, нажмите «Добавить ключ» и укажите название,
адрес поставщика и ключ. Если уже выбрано подключение, новая форма предлагает его адрес
и список моделей; ключ не копируется. OpenAI, OpenRouter и DeepSeek имеют готовые адреса.
Произвольные совместимые сервисы и агрегаторы поддерживаются через «Свой поставщик».

Доступны два режима:

- **Только отдельный адрес**: для OpenAI SDK — `/p/{id}/v1`, для Anthropic SDK — `/p/{id}`.
  Этот адрес всегда использует выбранное подключение, независимо от остальных ключей.
- **Общий и отдельный адрес**: ключ также участвует в общем `/v1/chat/completions` или
  `/v1/messages`. По полю `model` выбираются включённые подключения с этой моделью;
  запросы одной сессии, модели и формата API закрепляются за одним подключением.
  Новые сессии распределяются по ключам стабильным хешированием. Привязка проверяется
  при каждом запросе: отключённый, удалённый или больше не поддерживающий модель ключ
  заменяется подходящим.

Для собственной интеграции можно необязательно передавать `X-Kaponir-Session` с уникальным
ID диалога, постоянным между ходами. Это внутренняя метка привязки Kaponir, а не замена
сессии агента; она не передаётся поставщику. В стандартных примерах заголовка нет.
Без него используется хеш первого сообщения,
не являющегося system/developer: одинаковые начала диалогов имеют одну привязку.
Сжатие или обрезка истории может изменить первое сообщение и привязку. Для строгого
закрепления без настройки агента используйте отдельный адрес подключения.
Хранятся до 8192 привязок в памяти; вытесняется наименее недавно использованная.
Срок простоя задаётся `session_idle_hours`. При перезапуске, истечении срока или вытеснении
первоначальный выбор вычисляется заново; изменения привязки после 429 не сохраняются на диск.
Закрепление помогает повторно использовать prompt cache, но его наличие и срок жизни
определяются поставщиком; при смене ключа кэш может потребовать прогрева.

По умолчанию HTTP 429 возвращается клиенту без повтора, даже при нескольких ключах в пуле.
Переключение включается явно опцией «Переключать ключ при HTTP 429» (`retry_on_429` в API)
у исходного и резервного подключения. Она выключена также у ранее сохранённых подключений,
в которых этого поля ещё нет. В этом режиме общий адрес повторяет те же замаскированные
байты с другим включённым ключом для той же модели и того же адреса API (`base_url`),
сохраняя новую привязку для следующих ходов. Совпадение адреса не гарантирует общность
аккаунтов: включайте опцию только для взаимозаменяемых ключей и запросов с полной историей.
Для серверных разговоров, файлов или другого состояния, связанного с аккаунтом,
переключение следует оставить выключенным. В рамках одного
запроса каждый ключ пробуется не более одного раза (максимум 64 попытки). Если все
подходящие ключи вернули 429, клиент получает последний ответ, включая `Retry-After`.
Ожидания и общего карантина ключей нет: другие сессии могут получить свой 429 и переключиться.
Прочие HTTP-ошибки, сетевые сбои и уже начатые ответы/SSE не запускают повтор.
Отдельный адрес не переключается на другой ключ даже при 429.
Балансы и квоты поставщиков остаются отдельными. По умолчанию новый ключ используется
только через отдельный адрес. Добавление ключа в общий пул — явная настройка.

### Модели и проверка

«Получать модели автоматически» включён по умолчанию. При сохранении подключения прокси
запрашивает у поставщика `GET /v1/models`, сохраняет найденные ID и сразу обновляет общий
каталог. При использовании общего или отдельного адреса каталог обновляется не чаще одного
раза в пять минут. В UI видны время последнего обновления и ошибка, если обновление не удалось;
последний успешный список остаётся доступным. Ключ и ответы модели в панель не возвращаются.

Поддержана пагинация через `after_id` и `last_id`: максимум 20 страниц, 1000 моделей и 2 МиБ
ответа. При некорректном курсоре каталог помечается ошибкой и не заменяется неполным списком.
Если поставщик не поддерживает discovery, снимите автоматический режим и укажите модели вручную,
по одному ID на строку. Кнопка проверки остаётся для немедленного обновления до сохранения.

Общий `GET /v1/models` объединяет **сохранённые** списки включённых подключений общего пула,
убирает дубликаты и исключает изолированные/отключённые ключи. Каталог не является онлайн-проверкой
доступности или квоты. Кнопки моделей в панели подставляют ID в пример SDK; реальную модель
каждого запроса выбирает клиент. Отдельный `/p/{id}/v1/models` проксирует список выбранного
поставщика (включая его параметры пагинации). Каталоги разных форматов API не смешиваются:
для общего Anthropic-каталога передайте `anthropic-version`, как это делает SDK.

При обновлении прежние одиночные профили сохраняют свои ключи, адреса и общий endpoint.
У них есть режим «Все модели — совместимость с прежней настройкой», который сохраняет
маршрутизацию без фильтра ID. Один такой профиль без списка моделей использует прежнее live
discovery; в многоключевом каталоге видны только явно сохранённые ID. После проверки моделей
панель предлагает перейти к явному списку. Прежние профили получают стабильные ID `openai`
и `anthropic`; новые — случайный ID, независимый от названия и ключа.

### Сохранение, отключение и удаление

«Сохранить подключение» применяет изменения к новым запросам без перезапуска. Уже начатые
запросы завершаются с прежними настройками. Переключатель «Подключение включено» временно
исключает ключ из общего пула и блокирует его отдельный адрес. Удаление подтверждается
в самой форме. После удаления отдельный адрес отвечает 404, после отключения — 503.
Если для модели нет подходящих ключей в управляемом общем пуле, запрос останавливается
с 503; он не отправляется незаметно поставщику из конфигурации.

Зашифрованный реестр хранится в `meta` vault под ключом `providers:v2`. Первая запись
переносит старые профили в реестр; пустой реестр не восстанавливает удалённые профили.
Изменения защищены общей блокировкой vault в процессе, поэтому параллельное добавление
ключей не теряет другие подключения. API возвращает настройки и `key_saved`, но не секрет.
Пустое поле ключа сохраняет прежний ключ только при неизменном нормализованном адресе
**того же подключения**. При смене адреса нужно ввести ключ заново.

Ключи шифруются ChaCha20-Poly1305 существующим master key vault; браузерное хранилище их
не содержит. Поле очищается после сохранения. Профили переживают перезапуск и восстанавливаются
из резервной копии vault вместе с master key. Удаление исключает ключ из активного реестра;
это не отзыв ключа у поставщика и не обещание физического стирания из старых резервных копий.
Допускается HTTPS и HTTP на loopback, редиректы отключены. Тела ошибок проверки поставщика
не возвращаются в панель, поскольку могут содержать секреты.

Сохранённые подключения имеют приоритет над `serve.*_upstream` и CLI-параметрами для
управляемого формата. Форматы, для которых подключения ещё никогда не добавлялись, сохраняют
прежний режим: адрес из конфигурации, ключ передаёт клиент. Для конфигурационного
`*_upstream` по-прежнему нужен адрес без конечного `/v1`; форма принимает оба варианта.

### Доступ, события и API

Все endpoints используют общий токен Kaponir (`serve.api_token`), если он задан:
`Authorization: Bearer` или `x-kaponir-token` для прокси. В примере Anthropic используется
`auth_token`, а в запрос поставщику подставляется его `x-api-key`. Без токена локальный SDK
может использовать фиктивное значение `kaponir-local`. Токен Kaponir не уходит поставщику.
Отдельный endpoint выбирает ключ, но не создаёт отдельную роль или границу доступа клиента.

События прокси включают безопасный `connection_id`, чтобы различать подключения.
Названия подключений и ключи в историю трафика не попадают.

- `GET /api/v1/connections` — список подключений и управляемых форматов.
- `POST /api/v1/connections` — создать подключение.
- `PUT /api/v1/connections/{id}` — обновить подключение; формат API неизменяем.
- `DELETE /api/v1/connections/{id}` — удалить подключение.
- `POST /api/v1/connections/test` — проверить черновик, при редактировании передать `id`.

JSON создания/обновления: `kind`, `name`, `base_url`, `api_key`, `enabled`, `pool`, `models`.
Поле `all_models` предназначено для явного режима без фильтра (в UI — совместимость старых
профилей). `pool` по умолчанию выключен. Пустой список без `all_models` недопустим для общего пула.
Старые `/api/v1/providers*` сохранены для совместимости; новые клиенты должны использовать
`/api/v1/connections*`.
