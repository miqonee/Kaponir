# Кандидаты, оценка S1 и накопление предложений

[Документация](README.md) · [Команды](COMMANDS.md#discover) ·
[S1](S1.md) · [Безопасность](SECURITY.md)

Для каталога, PDF/изображений и фонового запуска используйте [отдельный worker](WORKER.md).
Он сохраняет кандидатов в ту же подборку.

`discover` помогает подготовить профиль конфиденциальных значений по документам.
Он не просматривает фоновый трафик и не меняет автоматические детекторы прокси.
Стандартный предпросмотр локальный, не сохраняет предложения и не вызывает S1.

## Поиск и примеры

К существующим незамаскированным кандидатам добавлены локальные эвристики:

- суммы с валютой;
- составные названия после меток проекта, компании/организации и клиента;
- названия в кавычках, в том числе JSON-значения;
- идентификаторы с цифрами после меток договора, ticket, customer_id/client_id.

Например, `Проект: Северный Вектор` предлагает целиком `Северный Вектор`.
Более короткая находка детектора внутри этого названия не дублирует предложение.
Уже полностью замаскированные значения и значения под явным KEEP не предлагаются.
Кандидаты, пересекающиеся с найденными учётными данными, исключаются из discover.
Это эвристики, не универсальный NER: пропуски и лишние предложения возможны.

Для каждого значения показываются число вхождений, число документов и до трёх
примеров употребления. Позиции start/end — смещения UTF-8 в байтах. Пример содержит
короткое окно текста с маскированием остальных найденных значений. Полный документ
во внешний S1 не передаётся. Нераспознанные чувствительные сведения в окне могут
остаться открытыми; для минимального раскрытия используйте L0.

## Явная оценка S1

```sh
kaponir discover contract.txt public-prices.txt --s1 --json
```

Используются текущие настройки S1 (включая тайм-аут, калибровку и L0/L1/L2):

- L0: только признаки;
- L1: признаки и само значение;
- L2: дополнительно контекст, где скрыты другие локально найденные значения.

Discover не отправляет отдельный список подтверждённых правил S1. На уровне L2
контекст ограничен настройкой context_bytes, максимум 4096 байт с каждой стороны.
Каждый пример оценивается отдельно: одинаковая сумма в закрытом предложении и
публичном справочнике может получить разные оценки. Оценки показаны возле примеров,
не превращаются в порог для автосохранения и не являются обучающими метками.
Shadow/active не меняют это поведение discover: он только предлагает.

При выключенном S1, недоступном сервисе, тайм-ауте или неверном ответе локальные
предложения сохраняются; статус сообщает об отсутствии оценки. Количество S1
операций/ошибок отражается в диагностике. После применения правил S1 повторно
не вызывается: подтверждаются только значения, проверенные сервером.

## Зашифрованная подборка

```sh
kaponir discover contract.txt --s1 --remember
kaponir discover invoice.txt --remember
kaponir discover --saved --json
kaponir discover --saved --select <ID> --scope team
kaponir discover --saved --reject <OTHER_ID>
```

`--remember` объединяет предложения в encrypted private setting vault. Хранятся
значения, короткие маскированные примеры, оценки и отпечатки документов; полные
документы не сохраняются. Подборка переживает перезапуск. Отпечаток учитывает имя
и содержимое документа: повторная загрузка того же текста под тем же именем
не увеличивает счётчики. Изменённый документ или другое имя считаются новым
источником. Различия регистра объединяются; пробелы и пунктуация не нормализуются.

`--saved` читает подборку без исходных файлов, показывает ранее сохранённые оценки.
Чтобы получить новые оценки, заново проанализируйте исходные документы с `--s1`.
Сохранённые оценки не пересчитываются автоматически при смене модели.

В панели: **Настройки → Правила из документов**. Флажки оценки и накопления
по умолчанию выключены. «Открыть подборку» загружает накопленные предложения.
Ни одно предложение заранее не отмечено для применения.

## Подтверждения и обучение

- «Применить выбранное» / `--select`: точное MASK-правило и положительная метка.
- «Не чувствительное — для обучения» / `--reject`: отрицательная метка, без
  KEEP-правила и без изменения текущих решений маскирования.
- Снятие выбора или отсутствие действия: никакой метки.

Решённые предложения убираются из подборки и не добавляются туда повторно.
Локальный предпросмотр исходных документов остаётся независимым от истории
отклонений: его можно использовать для повторной оценки и исправления метки.
Повторное явное решение заменяет прежнюю метку того же значения и типа.

```sh
kaponir s1 train
```

Обучение использует подтверждённые метки вместе с точными правилами и решениями
журнала. Повторы не увеличивают вес примера; конфликтующие метки одного значения
исключаются. Нужно минимум по три разных значения каждого класса. Обучение
запускается вручную; ответы S1 сами в набор обучения не попадают. Метки значения
не являются обучением контекстной модели: если конфиденциальность зависит от
ситуации, не назначайте универсальную положительную/отрицательную метку.

Подборка и метки — данные vault; они не входят в экспорт настроек. Принятые правила
экспортируются обычным способом. Для переноса всей истории нужна копия vault.

## Ограничения нагрузки

Один запрос: до 64 документов, до 2 МиБ текста, имя документа до 1024 байт.
Локальный отчёт: до 256 значений, до трёх примеров каждого. S1: до 96 примеров
одним вызовом провайдера; остальные остаются без оценок, статус будет `partial`.
Оценивание идёт в стабильном порядке, а не по величине предполагаемой оценки.
Превышение лимита кандидатов отмечается `truncated`.
Подборка: до 1000 значений, до 256 источников одного значения; до 10000 подтверждённых
меток. При переполнении хранилища операция отклоняется без усечения прежних данных.

## API

- `POST /api/v1/ui/discover`: `{documents, use_s1:false, remember:false}`.
- `GET /api/v1/ui/discover/profile`: `{report, labels}`.
- `POST /api/v1/ui/discover/apply`: `{documents, ids, scope, action:"mask"}`;
  для подборки `saved:true`, исходные документы не нужны.
  `action:"not_sensitive"` сохраняет только отрицательные метки.

API принимает идентификаторы предложений, не готовые значения, вероятности или
пользовательский отчёт. Все методы используют обычную авторизацию Kaponir.
