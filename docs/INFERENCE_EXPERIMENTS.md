# Контекст, разбиение и независимая классификация

12 ноября 2026. Продолжение [исходного сравнения трёх моделей](MODEL_COMPARISON.md).

## Причина обрыва Qwen

На обычной **Qwen3.5-2B-Q4_K_M** повторён первый фрагмент синтетического лога
из исходного сравнения: 6000 UTF-8 байт, контекст 4096, выход до 1600,
llama.cpp b12038, CPU, два потока, один слот, temperature=0, thinking выключен.

| Наблюдение | Значение |
|---|---:|
| `prompt_tokens` | 3201 |
| `completion_tokens` | 895 |
| `total_tokens` | 4096 |
| `finish_reason` | `length` |
| Процесс после ответа | жив |
| Лимит памяти окружения | 8 GiB |
| Накопленные `oom / oom_kill` | 0 / 0 |

Это исчерпание общего контекста. Лимит выхода 1600 ещё не достигнут.
У Huihui ранее воспроизведены те же числа. Объём в байтах не резервировал место
для ответа и по-разному расходовал контекст разных токенизаторов.

В повторе обычной Qwen второй фрагмент дал 12 точных значений, но первый оборвался.
Старый обработчик отменял весь документ, теряя пригодный ответ другого фрагмента.
Эти 12 значений в новом исследовательском отчёте являются **частичным результатом**,
а не успешной обработкой лога. Показатель первоначального приложения «лог: сбой»
остается верным для той версии.

Нулевые счётчики относятся к этому окружению и этим воспроизведениям. Они не
устанавливают причину любого сбоя на другой машине или с другим лимитом Docker.

## Данные и подсчёт

Использован [фиксированный синтетический корпус](../tests/docs/README.md):
8 документов, 49 089 байт, 219 разных конфиденциальных значений и 363 вхождения.
SHA-256 набора: `1815af85ae5198240fac4d9aaff659d33e35779f5bc1ae621699afafc370ce92`.
Файлы и арифметика сметы проверены `check_learning_corpus.py`.
В модель передаются только исходные документы; эталон остаётся у оценщика.
Организации, контакты, адреса и ключи вымышлены.

Для настройки использовались смета `01-cost-estimate.md` — 67 значений,
лог `02-application.log` — 25 и отрицательный контроль `08-public-reference.md` — 0.
Оставшиеся пять документов дают 127 дополнительных значений. Совпадение — точный
текст в правильном документе, включая пробелы и валюту. Частичный телефон,
адрес или целая строка таблицы вместо суммы не засчитываются. Предложения вне
эталона и срабатывания в полностью публичном документе считаются отдельно.
Самооценка модели не используется как измеренная точность.

Есть два разных слоя измерений:

- Исходное сравнение и `evaluate_external_model.py` используют настоящий API
  приложения: чистое тестовое пространство, категоризация и автоактивация выключены.
- `experiment_inference.py` измеряет цитируемые предложения модели **до фильтров
  приложения**. Он исключает выдуманные значения и повторы, но допускает
  неправильные границы выделения и лишние публичные значения для дальнейшей оценки.

Сырые результаты нельзя напрямую выдавать за точность всей системы маскирования
или сравнивать с отфильтрованными предложениями без указания слоя.

## Локальные эксперименты

GGUF и runtime закреплены SHA-256 из [каталога исходного сравнения](MODEL_COMPARISON.md#закреплённые-артефакты).
Все генерации локально используют два потока, один слот, контекст 4096,
выход 1600, temperature=0, без thinking, GPU и vision. Поиск не создаёт правил.

Проверены следующие варианты:

- Разбиение по реальному токенизатору с сохранением абзацев и структурного контекста.
- Дополнительный целевой вход 1024 токена, структурный контекст до 256 токенов.
- Поиск только значений и confidence, с отдельным определением типа.
- Независимый пересмотр без исходной ошибочной подсказки типа.

| Модель и профиль | Точно / 92 | Смета / 67 | Лог / 25 | Вне эталона | Публичный контроль |
|---|---:|---:|---:|---:|---:|
| Huihui: auto, typed, контекст фрагмента 256 | 16 | 6 | 10 | 40 | 13 |
| Qwen3.5-2B: вход 1024, values, контекст 256 | 48 | 32 | 16 | 56 | 8 |
| MiniCPM5-2B: вход 1024, values, контекст 256 | 41 | 31 | 10 | 20 | 1 |

Все девять документов этих трёх прогонов завершились без обрыва. Здесь варьировались
профили; таблица не является новым рейтингом трёх моделей в одинаковых условиях.
Для Qwen и MiniCPM поисковая политика одинаковая. Общий профиль всех трёх до изменений
зафиксирован в исходном сравнении. Повышение полноты не означает повышения точности:
у Qwen 48 из 104 предложений совпали с эталоном, у MiniCPM — 41 из 61.
Для MiniCPM новый режим также не даёт оснований заменить им прежний поиск
с 38 совпадениями среди 40 предложений приложения: это другой слой и компромисс.

Маленький фрагмент не гарантирует правильное выделение. Qwen, например, возвращала
части телефонов, публичные технологии и целые строки таблицы вместо отдельных
денежных значений. Это отличные от обрыва ошибки: увеличение лимита само их не исправит.
Режим `values` поэтому доступен для настройки, а не объявлен универсальным победителем.

Первый пробный вариант ошибочно считал заполненный список достаточным основанием
для дальнейшего деления. Huihui выдала 24 записи, но только 8 разных цитируемых
значений. После устранения повторов это не заполнение полезной ёмкости списка.
В приложении и исследовательском инструменте деление по насыщению теперь учитывает
разные значения из исходника. Корректные предложения родительского фрагмента
сохраняются при последующей проверке частей.

Часть поисковых прогонов совпала по времени со сборками и браузерными проверками
при общей квоте CPU=2. Их wall time не используется для вывода о сравнительной
скорости моделей. Для качества и протокола сохранены настройки, usage, finish reason
и ошибки. Это ограниченный перебор профилей на синтетическом наборе, не доказательство
глобального оптимума параметров.

## Пересмотр типов

12 фиксированных проб: семь публичных значений должны получить KEEP; у пяти
конфиденциальных намеренно ошибочно указан тип. Это Thu/Nov, логин, цена,
публичный процент, Git ref/node ID, часть частного пути, публичный инструмент,
название проекта, ФИО и количество работ.

| Huihui, одна и та же GGUF | Верный MASK/KEEP / 12 | Исправлен тип / 5 | Верный scope / 5 |
|---|---:|---:|---:|
| Исходная инструкция и подсказка ошибочного типа | 6 | 0 | 4 |
| Та же инструкция, подсказка типа удалена | 6 | 3 | 4 |
| Независимая классификация, подсказки нет | 10 | 5 | 5 |

Значит, склонность копировать исходную метку действительно мешала исправлению;
одного удаления поля недостаточно для хорошего решения MASK/KEEP.
В продукте исходная метка остаётся в истории, а модель получает значение и цитату.
Для пересмотра используется инструкция на независимую классификацию.

| Дополнительные пробы | Верный MASK/KEEP / 12 | Тип / 5 | Scope / 5 | ID |
|---|---:|---:|---:|---|
| Qwen3.5-2B, независимая инструкция | 10 | 5 | 5 | смысловые, калибровка |
| MiniCPM5-2B, независимая инструкция | 10 | 4 | 4 | непрозрачные |

У этих двух проверок различается вид ID, поэтому разницу баллов нельзя
приписать только модели. В MiniCPM оставалась ошибка типа в пробе `login` и две ошибки решения MASK/KEEP; причины и исходные ответы сохранены в артефакте.

Исходные калибровочные пробы имели смысловые ID вроде `price` и `login`; это само
по себе возможная подсказка. В приложении ID непрозрачные. Новый инструмент по
умолчанию также хеширует ID; `--no-opaque-review-ids` нужен только для повторения
исторической калибровки. Настройка инструкции по этим 12 пробам не заменяет проверку
на новых документах и не делает самооценку LLM калиброванной вероятностью.

Исправлена одна несогласованность эталона: закрытая коммерческая цена должна иметь
scope `global`, как в основном корпусе. В старой фикстуре стоял `personal` по
умолчанию приложения. Таблица выше пересчитана по единой политике без изменения
ответов моделей; первоначальный отчёт сохранён исторически.

## Внешний провайдер

Проверен заданный маршрут `ag/gemini-3.8-flash`; ответы сообщают модель
`gemini-3.8-flash-n`. Это идентификатор шлюза, а не независимо проверенная
идентичность базовой модели. Запросы имеют temperature=0; внутренние reasoning
и дополнительные инструкции провайдера отличаются от локального runtime.

Шлюз принимал `response_format: json_schema`, но возвращал Markdown-блоки,
массив вместо объекта и типы вроде `organization` вместо `ORG`. Поэтому первый
прогон старого клиента не является оценкой качества модели. Зафиксированы и HTTP 503;
они учитываются как транспортные сбои, отдельно от пропущенных значений.

Дублирование полной JSON-схемы в инструкции устранило эти нарушения формата.
При старой формулировке поиска, без требования перечислить каждое значение,
на восьми документах модель дала **125/219** точных предложений, все 125 — в эталоне,
без находок в публичном контроле. В отдельных 12 пробах пересмотра: **12/12**
действий, **5/5** типов, **4/5** scopes. Цена получила `team` вместо эталонного `global`.

Затем на одной и той же смете изменено задание: перечислить **каждое** отдельное
конфиденциальное значение, включая все строки таблиц, без резюмирования.
Контекст 32768, выход 4096, максимум 128 кандидатов, тип на этапе поиска не запрашивается.

| Условие | Точно / 67 | Вне эталона | Генераций |
|---|---:|---:|---:|
| Старая формулировка, весь документ | 19 | 0 | 1 |
| Полное перечисление, весь документ | 67 | 0 | 1 |
| То же полное перечисление, целевой вход 4096 | 65 | 0 | 5 |

При разбиении пропали две организации. Следовательно, сильной модели деление
может мешать; жёсткое правило «всем по абзацам» не обосновано. Полное перечисление
помогло без уменьшения документа. Прогоны единичные; температурой 0 нельзя гарантировать
идентичный ответ удалённого маршрута при повторении.

В финальном прогоне через **настоящий API приложения** использованы все восемь
документов и режим полного перечисления `values`, контекст 32768, выход 4096,
целевой вход 0, структурный контекст 256, максимум 128 кандидатов.

|---|---:|---:|---:|

Полнота точного выделения — **87.7%**, доля точных совпадений среди
предложений — **99.0%**. Все восемь заданий завершены, публичный контроль — 0.
Два предложения вне эталона — URL с протоколом/путём вместо размеченного hostname;
это различие границ выделения, а не две доказанные ошибки конфиденциальности.
Категоризация и автоактивация выключены: эти числа относятся к обнаружению.

Окружение перезапустило процессы во время серии. Четыре завершённых документа
восстановлены из изолированного Vault; источники четырёх оставшихся побайтно
сверены с фикстурами локальным `verify_lab_home`, без внешних запросов.
Незавершённая часть продолжена с тем же адресом получателя и профилем.
В финальной серии не было HTTP-ошибок и явных повторов после HTTP-ошибок;
четыре завершённых после перезапуска обращения записаны отдельно от ранних
диагностик, поэтому время возобновления нельзя выдавать за время полного прогона.

## Что изменено в приложении

- Локальный бюджет измеряется через `/apply-template` и `/tokenize` загруженной GGUF;
  выход и резерв вычитаются до генерации. Проверка простого запроса дала точное
  совпадение предсказанного числа токенов с `usage.prompt_tokens`.
- Доступны `auto` и `paragraph`, целевой вход, бюджет структурного контекста,
  предел находок, предел обращений, режим `typed`/`values` и размер пакета пересмотра.
  У обнаружения и категоризации свои бюджеты. Настройки спрятаны в дополнительных
  параметрах, пояснения — в вопросниках.
- При обрыве ответа источник делится повторно; пригодные результаты других частей
  сохраняются для подтверждения. Частичный результат не создаёт правил автоматически.
- Пересмотр и локальная/OpenAI-категоризация не получают ошибочный исходный тип.
  Категоризация может вернуть KEEP. Исходные оценки детекторов не переписываются.
- История содержит модель и числовую диагностику завершения, без исходников,
  секретов и полного текста ответа. Для локального runtime различаются расход
  контекста и лимит ответа; неизвестный предел внешнего сервиса так и обозначается.
- Повторная загрузка после изменения профиля не переиспользует чужой результат
  из кэша. Изменение настроек само не пересылает прежние документы новому адресату.

Пределы не выбираются по названию модели или документа. Стартовые значения
4096/1600/64 — редактируемые настройки совместимости, а не оценки вместимости GGUF.
Для API без токенизатора используется консервативная оценка UTF-8 байт и сохраняется
usage сервиса; скрытые инструкции сервиса заранее неизвестны.

## Воспроизведение

```sh
cargo build --release --locked -p kaponir-cli
python3 scripts/check_learning_corpus.py --output artifacts/inference-lab/corpus-validation.json
python3 scripts/experiment_inference.py \
  --model qwen3.5-2b --model-dir /path/to/models --runtime /path/to/llama-server \
  --strategy auto --candidate-mode lean --target-input-tokens 1024 \
  --hint-tokens 256 --blind-review --output artifacts/inference-lab/local
```

`--strategy fixed` воспроизводит старые 6000 байт / перекрытие 256;
`--review-only` проверяет только 12 проб, `--skip-review` — только документы.
Чтобы сравнить профили через настоящий внешний API приложения, передайте файл
с `inference` и `chunking` в `--profile`:

```sh
python3 scripts/evaluate_external_model.py target/release/kaponir \
  --url https://route.fn.x3dev.ru/v1 --model ag/gemini-3.8-flash \
  --key-file /path/to/temporary-key --profile /path/to/profile.json \
  --output artifacts/inference-lab/external
```

Ключ читается из отдельного файла либо `KAPONIR_EVAL_API_KEY`; в отчёт и репозиторий
он не попадает. `--retry-failed` явно повторяет транспортные сбои через API заданий,
с записью всех попыток. Это не скрытая автоподстановка успешного ответа вместо сбоя.

## Проверки реализации

- 190 Rust-тестов; Clippy для workspace и всех targets без предупреждений.
- 63 Python-теста: токены и резерв, Unicode, структурное разбиение, пакеты с
  разным контекстом, обрывы, безопасная диагностика, JSON и перенаправления API.
- Браузерные проверки обучения, разборов решений и выбора/HF-импорта моделей:
  русская/английская версии, светлая/тёмная темы, 390/1440 px.
- Детерминированный HTTP-сценарий проверяет повтор обрезанного фрагмента,
  заполненный список, дубликаты, сохранение частичного результата, отсутствие
  автоактивации неполного результата и повторный поиск после смены профиля.

Числовой снимок всех завершённых экспериментов: [INFERENCE_RESULTS.json](INFERENCE_RESULTS.json).
Сырые ответы, usage и документы проверок находятся в `artifacts/inference-lab/`;
каталог артефактов исключён из Git. Для новых сравнений используйте чистое
тестовое пространство и храните исходный результат каждого прогона отдельно.
