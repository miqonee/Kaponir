# Перенос настроек между CLI и Web UI

[Документация](README.md) · [Команды](COMMANDS.md#перенос-настроек) ·
[Безопасность](SECURITY.md#экспорт-настроек--не-backup)

В разделе **Настройки → Перенос настроек** экспортируется JSON формата
`kaponir-settings`, версия `1`. Файл можно скачать, выбрать для импорта либо
вставить его содержимое в поле JSON. Кнопка «Применить настройки» заменяет
параметры, правила всех трёх контуров и список подключений.

CLI использует тот же формат и тот же код проверки и сохранения:

```sh
kaponir config export --output settings.json
kaponir config import settings.json
# Перенос на новую машину с ключами:
kaponir config export --include-secrets --output settings-with-keys.json
kaponir --home /path/to/new-space init
kaponir --home /path/to/new-space config import settings-with-keys.json
```

Экспорт CLI создаёт новый файл с правами 0600 и не перезаписывает существующий.
В вебе по умолчанию выключен флажок включения ключей.

## Содержимое и применение

- `config`: владелец, префикс токенов, пакеты, политика, S1, параметры сервера и worker.
  Параметры `[worker]` и адрес `[serve].worker_url` переносятся; пути должны быть
  доступны в целевом окружении. Веса/runtime/очередь worker не включены.
- `rules`: полные правила и корпоративные домены `global`, `team`, `personal`.
- `providers`: подключения с прежними идентификаторами и адресами, модели,
  общий пул, явная настройка повторов 429 и отметки управляемых протоколов.
- При включении ключей: ключи подключений, сохранённый в vault ключ S1,
  `config.serve.api_token`. Файл **не зашифрован**. Значения переменных окружения
  в экспорт не входят; имена переменных остаются ссылками.

Без ключей экспорт по-прежнему содержит точные значения пользовательских правил,
адреса и имена подключений. Это файл настроек для владельца пространства.
Отсутствующий ключ подключения сохраняется только при совпадении его id,
протокола и адреса. Новое подключение без ключа импортируется отключённым;
введите ключ на странице подключения и включите его. Старый ключ S1 сохраняется
только для прежнего URL; отсутствующий токен доступа Kaponir сохраняет локальный.
Для удаления ключей используйте настройки соответствующего подключения/S1.

Веб-импорт сразу пересобирает движок и сбрасывает кэши маскирования и привязки
подключений. **После любого импорта перезапустите `kaponir serve`**: адрес
прослушивания, токен доступа, владелец и другие параметры процесса читаются при
старте. CLI-импорт не уведомляет уже работающий сервер.

Импорт проверяет версию, структуру, подключения и сборку движка до записи.
Файлы подготавливаются отдельно; при обычной ошибке записи изменения откатываются.
Операция не является распределённой транзакцией файловой системы и SQLite при
аварийном завершении процесса. Не выполняйте импорт параллельно с другими
изменениями настроек из CLI.

Это не резервная копия: таблицы восстановления оригиналов, ключи vault/HMAC,
журнал и сессии не переносятся. Зашифрованная подборка discover и её обучающие метки
также относятся к данным vault и в файл настроек не включены; принятые MASK-правила
переносятся как обычные правила. Данные внешних пакетов и обученная модель S1
также не включены; соответствующие файлы должны существовать по указанным путям
на целевой машине, иначе импорт отклоняется. Для восстановления старых токенов
нужна отдельная резервная копия хранилища.

## API веб-панели

Оба метода защищены тем же токеном доступа, что остальные `/api/v1/*`:

- `POST /api/v1/ui/config/export`, тело `{"include_secrets":false}` → сам JSON;
  ответ имеет `Cache-Control: no-store`.
- `POST /api/v1/ui/config/import`, тело — экспортированный JSON →
  `{"imported":true,"restart_required":true}`.
