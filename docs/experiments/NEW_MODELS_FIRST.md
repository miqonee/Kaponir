# Сначала новые модели на уже проверенном протоколе

17 ноября 2026 года пользователь уточнил порядок: использовать накопленный корпус
семи моделей и подобранные prompts, сначала проверить восемь новых вариантов.
Массовый повтор прежних семи не требуется. Подготовленный проект такого повтора
отменён до регистрации и запуска; он не попал в Git и не сделал модельных вызовов.

## Что уже есть

Архив содержит все шесть схем для семи моделей: 42 результата на трёх прежних
синтетических документах. Их SHA, разметка, детекторный пул и оценки проверяются
без новой генерации. A–D полностью наблюдены у шести старых моделей после
дополнений транспорта; у Nanbeige в этой отдельной серии ответы ещё отсутствуют.
Свежие RU/EN — следующий этап проверки переноса, не основание повторять старый корпус.

Подбор prompts сохраняется. D — текущий лучший вариант Gemma для решения о
приватности заранее найденных целей. Перепоиск записей — отдельная задача;
в архиве здесь выделяется Nanbeige. Это разные контракты, их таблицы не объединяются.

## Первый полный прогон новых восьми

Выбран существующий протокол `nanbeige-calibration--result.json.gz`: все шесть
прежних схем, те же документы, детекторный пул, PRIMARY/AUDIT/REGION prompts,
prompt извлечения, типы и разметка. Выбор сделан по прежнему результату перепоиска,
не по ответам новых моделей на свежих документах. Приватность и правила заново
для каждой модели не подстраиваются.

| Параметр | Значение существующей опоры и новых запусков |
|---|---|
| Контекст / ответ | 4096 / 1600 токенов |
| Повтор с большим ответом | Нет |
| Temperature / top-p / top-k / min-p | 0 / 0,95 / 40 / 0 |
| Seed | Не передаётся, как в архиве |
| JSON | Prompt-режим со схемой в инструкции |
| Thinking | Выключен; фактическое поведение шаблона дополнительно записывается |
| Ожидание HTTP и timeout Worker | 1200 / 1200 секунд |
| CPU / слоты / GPU | 2 / 1 / 0 |
| Runtime | Тот же закреплённый SHA `3e042c…` |

Сохранён и прежний алгоритм окон и префиксов. Это полный прежний набор документов
и схем, а не выдача всего документа одним запросом. Токенизатор и chat template
являются свойствами самой модели; их хеши и фактические размеры входа фиксируются.
Фоновая проверка GGUF может ждать до 600 секунд до запуска runtime; это подготовка,
она не продлевает измерительный HTTP-бюджет. Исправление устраняет ложный отказ
после 30 секунд проверки большого файла.

Старые архивы содержат несколько режимов: у Qwen/Huihui ожидание было 300 секунд,
у Gemma/Granite — 1200 и grammar, у Nanbeige — 1200 и prompt. У раннего MiniCPM
не все метаданные sampling/JSON явно записаны. Это точечный пробел метаданных,
а не отсутствие всего проверенного корпуса. Поэтому прямой совпадающий профиль
первого этапа — архивная Nanbeige и новые восемь; остальные прежние результаты
показываются со своими настройками. Единый строгий профиль всех 15 не заявляется.
Если дальнейший вывод зависит от другого архивного режима, повторить его можно
на нужной новой модели, сохранив прежнюю опору.

Первые полные результаты и фактическое применение собраны в
[сравнительной таблице](NEW_MODELS_RESULTS.md). Она заново читает старые ответы,
не повторяя генерацию, и показывает все шесть схем, технические отказы,
покрытие всех вхождений и справочные ресурсы.

## Исполнение и отчёт

`run_legacy_new_models.py` допускает ровно восемь новых ID. Сначала завершается
уже начатый малый срез; его 1536/512 и нативные sampling не подаются как равные
архивному протоколу. Затем идут три уже зарегистрированные короткие диагностики
Nanbeige, затем восемь полных запусков на прежнем корпусе. Диагностика времени
Nanbeige не является повтором его полного benchmark.

Прежняя расширенная очередь 69 заданий отложена до анализа этого этапа.
Её producers, команды и полученные данные сохранены. Новые свежие случаи,
парные политики и нативные профили остаются последующими отдельными проверками.
Неопределённая отправка не повторяется автоматически; полученные ответы не исправляются.

Подготовка без генерации:

```sh
python3 scripts/evaluate_model_schemes.py --prepare-only \
  --model lfm2.5-1.2b-instruct --profile common \
  --legacy-reference nanbeige42-3b --output /tmp/kaponir-reference-prepared
```

План связывает архивные и исходные SHA. Любое расхождение текстов, типов,
разметки, детекторного пула, sampling, лимитов или JSON-режима блокирует повтор
протокола. Отчёт заново оценивает сохранённые старые ответы и новые результаты,
разделяет сопоставимую опору и другие исторические профили. Время и ресурсы
остаются справочными; фактическое mask→restore проверяется отдельным этапом.
