# Проверенные общие исправления по результатам исследования

16 ноября 2026 года. Сравнение 13 моделей ещё выполняется; модель и нативный
профиль по умолчанию не выбраны. Следующие изменения улучшают обработку ответов
независимо от победителя и не меняют замороженные измерительные producer snapshots.

## Однозначное чтение ответа

В Rust-клиенте модели и локальном Python Worker одинаковые ключи внутри одного
JSON-объекта теперь отклоняются, включая вложенные и экранированные варианты.
Например, `{"action":"mask","action":"keep"}` не становится пригодным keep.
Неконечные числовые значения также не принимаются. Сохраняются обычные JSON-типы
и Unicode. Некорректный ответ получает безопасный код ошибки, без содержимого
ответа или произвольного ключа в пользовательском сообщении.

Это проверка формата, не новое измерение качества какой-либо модели. Совместимость
Rust-клиента с прежними JSON-fences сохранена; строгий исследовательский контракт
не становится задним числом более разрешительным.

## Ошибка строки не отменяет пригодных соседей

Продуктовый пересмотр сначала проверяет количество и однозначность ожидаемых ID
всего пакета. Неизвестный, повторный или отсутствующий ID отклоняет весь пакет.
После успешной привязки каждая строка проходит прежние проверки типа, формата,
scope, confidence и причины отдельно:

| Ответ | Сохранённое состояние | Применение |
|---|---|---|
| Корректный mask/keep | Пригодная рекомендация | После явного подтверждения |
| Корректный review | Нужен ручной разбор | Автоматическое применение недоступно |
| Неверный тип/форма/число confidence | Ошибка этой строки | Недоступно |
| Неоднозначная привязка ID | Ошибка всего пакета | Недоступно |

При ошибке одной строки сохраняются хорошие соседи и обрабатываются следующие
пакеты. Задание сообщает о частичном отказе; недопустимые action/kind/confidence
не сохраняются как применимая рекомендация. Ручное подтверждение, проверка свежести
и запрет пересмотра защищённых секретов сохранены. Пользовательские правила самим
получением рекомендаций не изменяются.

Отдельное решение о приватности в варианте D пока остаётся исследовательской схемой:
у Gemma оно уменьшило неприменимость, но сохранило две смысловые ошибки и один
лишний review. Его преимущество ещё проверяется на других моделях и свежих документах.
Результаты B/C не пересчитываются с ослабленным валидатором.

## Короткое явно выбранное значение применяется

Выделение `q7` в интерфейсе раньше проходило проверку, но молча пропускалось движком:
для него действовало ограничение длины автоматической памяти сессии. Теперь
явно выбранные значения этого документа применяются и при длине менее трёх символов.
В тексте `q7 q73 q7_1 q7` скрываются два целых `q7`, а `q73` и `q7_1` сохраняются.
Восстановление точное, следующая операция без выделений не маскирует `q7`.
Ограничение автоматической памяти сессии сохранено.

Проверены движок и реальный HTTP API; полный Rust workspace после изменения:
195 тестов, Clippy всех targets с `-D warnings` и rustfmt.

## Решение модели и фактическое скрытие — разные измерения

Новый [скрипт применения](../../scripts/apply_measured_privacy.py) проверяет
сохранённые пригодные MASK через настоящий API приложения, без новых вызовов модели.
Для каждого документа и каждого прохода создаётся отдельный временный home с S1 off.
Базовый проход использует детекторы; второй добавляет MASK только для данного
документа. KEEP не создаёт исключений, пользовательские правила не меняются.
CUSTOM/personal здесь — явные настройки применения, а не предсказанный моделью тип.

На исходном Gemma D/v1 проверены три синтетических документа, шесть mask→restore:

| Проверка | Детекторы | Детекторы + сохранённые MASK Gemma D |
|---|---:|---:|
| Размеченные приватные вхождения | 193 | 193 |
| Остались видимыми | 140 | 104 |
| Потеряно из 87 открытых контрольных вхождений | 0 | 0 |
| Точное восстановление | 3/3 | 3/3 |

Это частичное улучшение на тех же документах, которые использовались в калибровке.
Решения для 32 готовых целей не заменяют поиск всех приватных значений документа:
104 вхождения остаются видимыми. Это также не проверка переноса качества на
продуктовый prompt со сниппетами. Свежие документы и остальные модели ещё в очереди.

Команда для отдельного, ещё не существующего каталога результата:

```sh
python3 scripts/apply_measured_privacy.py \
  --result artifacts/privacy-policy-phase2/gemma-v2-telemetry/result.json \
  --binary artifacts/product-regression/target/debug/kaponir \
  --output artifacts/product-regression/application-gemma-D --variant D
```

Отчёт связывает SHA плана, результата модели и бинарника; считает сохранность
публичных контролей, видимые приватные и запрошенные MASK-вхождения, проверяет
точное восстановление и отсутствие изменений постоянных правил. Временный Vault
удаляется после проверки. Ранее полученные результаты не перезаписываются.

## Проверено на текущем коде

- 195 Rust-тестов всего workspace; Clippy всех targets с `-D warnings`; rustfmt.
- 265 Python-тестов при запуске `python3 -S` (одна проверка необязательной зависимости
  пропущена); синтаксис JavaScript; паритет RU/EN и ссылки документации.
- Локальный Chromium: 16 групп проверок пересмотра, включая смешанный пакет,
  запрет применения ошибочной строки, явное применение, rollback, RU/EN и мобильные размеры.
- Синтетический корпоративный корпус: 64 документа, 1344 размеченных значения,
  8808 вхождений; после подтверждённых правил нет утечек/потерь публичных контролей,
  все 64 mask→restore точны. Это регрессия движка, не результат LLM.
- Заново выполнен текущий `detector_candidates`: 163 вхождения, 94 уникальные
  пары «документ, значение»; канонический экспорт полностью совпал с опорным
  `04a3f06ee818443560762b375ccbf5b8642ae38c7892fb80345391ff0017e146`.

Журналы и изображения находятся в локальном `artifacts/product-regression/`.
Сопутствующее исправление CLI сохраняет код завершения `discover` при `init --learn`
и устраняет предупреждение Rust 1.100. Пользовательские данные для проверок не использовались.
