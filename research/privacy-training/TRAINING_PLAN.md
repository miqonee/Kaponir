# Протокол обучения и проверки v3

В пилоте сравниваем исходную Qwen3.5-2B и её LoRA на роли, границе и режиме раскрытия каждого значения. Единица оценки — вхождение в исходном документе. Получатель — внешняя модель. Новый контроль целиком синтетический. [Инструкция разметчика](ANNOTATION.md) · [Проверка перед обучением](reports/preflight-v3.md)

## Данные и доступ к эталону

Обучение использует 507 записей, валидация — 157. В независимом тесте 72 документа из 12 новых семей, 217 приватных вхождений, 182 публичных контроля и 18 спорных значений. У каждой семьи есть чистый запрос. Основная проверка содержит 63 документа с одним текстом и форматом. Ещё 9 документов образуют три серии с побайтно одинаковым текстом и разным доверенным статусом. В отчёте выводятся обе части и общий результат. Тест v2 из 163 документов служит регрессией и оценивается отдельно с той же инструкцией v3. [Замороженный манифест](data/v3/manifest.json)

Зафиксировать хеши входов, параметры и версию модели до обучения. Выбирать checkpoint только по `validation`. При разработке корпуса уже были просмотрены результаты детекторов и контроль с идеальной разметкой. После испытания модели изменения, подсказанные ошибками финального теста, требуют нового независимого контроля для следующего вывода о переносе.

## Подготовка данных и GPU

Команды выполняются из корня репозитория в Ubuntu под WSL2. Для RTX 4080 Laptop используем 12 ГБ выделенной VRAM и 32 ГБ системной памяти. Для окружения, весов и адаптеров заложить около 30 ГБ диска. Состояние CUDA, пик выделенной VRAM и время шага проверяются на самом ноутбуке. [CUDA в WSL2](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

```sh
pilot=research/privacy-training
run=artifacts/privacy-training/pilot-v3
mkdir -p "$run"
python3 -m venv "$run/venv"
. "$run/venv/bin/activate"
python -m pip install --index-url https://download.pytorch.org/whl/cu128 torch==2.8.0
python -m pip install -r "$pilot/requirements-pilot.txt"
nvidia-smi
python -c 'import torch; print(torch.cuda.get_device_name(0), torch.cuda.is_bf16_supported())'
hf download Qwen/Qwen3.5-2B tokenizer.json chat_template.jinja --revision 15852e8c16360a2fea060d615a32b45270f8a8fc --local-dir "$run/assets"
python "$pilot/prepare.py" check --assets "$run/assets" --output "$run/inputs"
python "$pilot/prepare.py" check --assets "$run/assets" --data "$pilot/data/v2" --output "$run/regression"
python -m unittest discover -s "$pilot" -p test_pilot.py
cargo build --locked --release -p kaponir-cli
```

`prepare.py` проверяет хеши токенизатора и шаблона, границу между запросом и ответом, наличие стоп-токена и точный обратный переход от окон к документу. Общий бюджет 1024 токена, резерв генерации 256. Длинный текст делится до показа эталона общим алгоритмом воркера по абзацам, строкам и пробелам. После этого аудит сверяет, что каждое эталонное значение целиком помещается в окно. У каждого окна свои локальные номера вхождений. `join` привязывает их к байтам оригинала, проверяет хеш всего документа и восстанавливает глобальные номера. В файлах `*-windows.jsonl` нет эталонных ответов. [Подготовка](prepare.py)

## Обучение и выбор checkpoint

До расходования GPU-времени сравнить штатные публичные потери с допустимым бюджетом. В текущем прогоне это 50 из 211 на валидации при максимуме 4. Алгоритм добавляет маски, поэтому в такой конфигурации итог отбора уже известен — ни одна эпоха не пройдёт граничный порог. Дообучение сохраняет отдельный исследовательский смысл для точности и полноты разметки самой Qwen. Любое изменение того, какие штатные решения разрешено пересматривать, требует отдельного эксперимента с повторной проверкой приватных вхождений. [Зафиксированный результат](reports/preflight-v3.md)

| Параметр | Зафиксированное значение |
|---|---|
| Базовая модель | `Qwen/Qwen3.5-2B@15852e8c16360a2fea060d615a32b45270f8a8fc`, BF16 |
| Адаптер | Ранг 16, alpha 32, dropout 0. Языковые проекции внимания, линейного внимания и MLP. Визуальный энкодер заморожен |
| Оптимизация | AdamW, постоянный LR `1e-4`, weight decay 0, отсечение нормы 1, один пример на GPU и накопление по 4 |
| Обучаемая часть ответа | Только токены содержимого ответа и завершения после общего префикса Qwen. `enable_thinking=False`, без обрезки эталонов |
| Воспроизводимость | Seed 42, фиксированные части, две эпохи, по одному адаптеру после каждой |

```sh
python "$pilot/laptop.py" train --stage smoke --assets "$run/assets" --output "$run/smoke"
python "$pilot/laptop.py" train --stage full --assets "$run/assets" --output "$run/full"
```

`smoke` выполняет 20 шагов оптимизатора, сохраняет и повторно загружает адаптер, генерирует один ответ на валидации. Проверить конечный loss, `smoke_answer`, пик VRAM и время шага. Полный запуск начинается с исходных весов и чистого адаптера. Версии пакетов и конфигурация сохраняются рядом с результатом. [Скрипт для ноутбука](laptop.py)

Для каждой эпохи провести измерение на валидации. Первый этап измеряет саму Qwen, второй пропускает её решения через исследовательский адаптер, штатные детекторы и локального HTTP-получателя.

```sh
for e in 1 2; do
  dir="$run/val-$e"
  mkdir -p "$dir"
  python "$pilot/laptop.py" predict --windows "$run/inputs/validation-windows.jsonl" --adapter "$run/full/epoch-$e" --assets "$run/assets" --output "$dir/windows.jsonl"
  python "$pilot/prepare.py" join --windows "$run/inputs/validation-windows.jsonl" --answers "$dir/windows.jsonl" --output "$dir/predictions.jsonl"
  python "$pilot/replay.py" --binary target/release/kaponir --split validation --predictions "$dir/predictions.jsonl" --output "$dir/observations.jsonl"
  python "$pilot/evaluate.py" --split validation --predictions "$dir/predictions.jsonl" --observations "$dir/observations.jsonl" > "$dir/metrics.json"
done
python "$pilot/laptop.py" select --epoch1 "$run/val-1/metrics.json" --epoch2 "$run/val-2/metrics.json"
```

К отбору допускается полный измеренный прогон с точным восстановлением и максимум 2% затронутых публичных контролей на валидации. Среди прошедших выбираем наибольшую полноту точных модельных меток `mask`, при равенстве — более раннюю эпоху. Значение `selected_epoch: null` означает, что обе эпохи не прошли условия. В таком случае сохраняем валидационные результаты и регистрируем отсутствие подходящего checkpoint.

## Финальная проверка и метрики

Для каждого теста отдельно сравнить три варианта на тех же документах. Для штатных детекторов запустить `replay.py` с одним `--binary` и указанием набора и результата. Исходная Qwen использует `laptop.py predict` без `--adapter`, выбранная LoRA использует `--adapter`. Обеим подаются те же `test-windows.jsonl`, жадное декодирование, одинаковые токенизатор и лимиты. Повторить последовательность `predict → join → replay → evaluate` с `--split test`. В регрессии указать каталог `data/v2` для `replay` и `evaluate` и брать окна из `regression`. Для кандидата передать также `--baseline-observations` с наблюдениями исходной Qwen, чтобы получить парную разницу и интервалы по семьям.

| Показатель | Подсчёт |
|---|---|
| Полнота защиты | Число эталонных `mask`, целиком покрытых заменами в захваченном запросе, делится на число всех `mask`. Частичное и открытое вхождения считаются отдельно и дают ноль в числителе. Цель ≥95% |
| Потери публичного контекста | Доля эталонных `keep`, у которых хотя бы один байт перекрыт фактической заменой. Цель ≤2% |
| Корректность ответа модели | Precision, recall и F1 при однозначном совпадении позиции, типа и действия. Считать FP, FN, неверный тип или действие, частичную границу, ошибки JSON, недопустимые вхождения и пропуски ответов. Показать по типам и действиям |
| Спорные значения | Считать `review` отдельно в разметке. На выходе скрывается только спорное значение. Если вместо ожидаемого `mask` модель ответила `review`, метка модели ошибочна, но фактическое покрытие всё равно измеряется |
| Сохранение контекста | Доля запросов с утечкой среди документов с приватными значениями, доля изменённых чистых документов, число затронутых байтов за границами всех меток |
| Обратимость и полнота наблюдений | Побайтовое совпадение восстановленного эха с исходным текстом в 100% документов. Отсутствие наблюдения делает прогон неполным и закрывает допуск |
| Перенос | В паре или тройке должны быть точны все ответы. Указывать число серий каждого вида. Общий оценщик проверяет каждый документ, включая пустые |

На v3 пороги составляют **минимум 207 из 217** приватных и **максимум 3 из 182** публичных вхождений. На v2 — **318 из 334** и **3 из 167**. Для сравнения исходной Qwen и LoRA считать разницу в процентных пунктах и 95%-й процентильный интервал по 2000 парным выборкам с возвращением, пересэмплируя целые группы с seed 42. Зафиксировать числители, знаменатели, число групп и входной статус. Пороги относятся к наблюдаемым долям на синтетике.

Файл предсказаний содержит JSONL-обёртки с `id` и сырым `response` либо массивом `spans`. JSON модели проверяется строго, включая повторяющиеся ключи. Файл наблюдений содержит `id`, `source_sha256`, захваченный `received`, байтовые `replacements` и фактически восстановленный `restored`. Повторный или неизвестный ID и повреждённая обёртка отклоняют файл. Отсутствующий ответ или ошибка формата относятся к документу. При ошибке модели в экспериментальной передаче продолжают работать детекторы.

Исследовательский адаптер сначала получает байтовые замены реального `kaponir mask` с отдельным хранилищем на документ. Затем закрывает видимые участки предложенных `mask` и `review`. Модельное `keep` сохраняет штатные решения. Санитизированный текст передаётся локальному HTTP-получателю, его эхо проходит обратную подстановку адаптера и `kaponir restore`. Такой запуск измеряет экспериментальную схему передачи. В штатном фоновом воркере находки пока объединяются по строке.
