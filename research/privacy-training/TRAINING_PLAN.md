# План обучения и проверки

## Что учим

Kaponir подставляет токены вместо конкретных конфиденциальных значений перед отправкой запроса внешней модели. Учим модель находить точные вхождения, различать рабочие значения и публичные примеры, а при неясном статусе выдавать `review`. Типичные цели включают `l.mireva` после `/home/`, две части `DOMAIN\user`, внутренний хост, ключ доступа и цену договора. Окружающая фраза, имена полей, стандартные части путей и разделители сохраняют смысл запроса.

Вход содержит исходный текст и формат. При наличии подтверждённого статуса публикации его можно передать отдельным полем. Выход содержит JSON с массивом `spans`. `value` дословно копирует подстроку. `occurrence` нумерует все её буквальные совпадения слева направо с единицы, включая пересекающиеся. `kind` задаёт тип Kaponir, а `action` принимает `mask`, `keep` или `review`. Движок восстанавливает байтовые координаты по исходнику. В эталоне `start_byte` включён, `end_byte` исключён.

```json
{"spans":[{"value":"l.mireva","kind":"USER","action":"mask","occurrence":1}]}
```

Источник разметки и внешняя политика для v0 и v1 описаны в [датасете](README.md). Для второго исходного набора `public` проецируется в `keep`, `internal` и `restricted` в `mask`, `unknown` в `review`. Это сценарий передачи внешней модели. Действующие правила движка продолжают защищать обязательные маски. `keep` в ответе модели относится к её собственным предложениям.

## Подготовка запуска на ноутбуке

Целевая система — RTX 4080 Laptop с 12 ГБ выделенной VRAM, 32 ГБ системной памяти и Ubuntu под WSL2. Для весов, окружения, кэша и сохранения адаптера заложить около 30 ГБ свободного диска. Проверить `nvidia-smi` внутри WSL2 и наличие CUDA с BF16 в установленном PyTorch. Использовать драйвер NVIDIA Windows для WSL2. [Руководство по CUDA в WSL2](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

```sh
nvidia-smi
python -c 'import torch; print(torch.cuda.get_device_name(0), torch.cuda.is_bf16_supported())'
python3 research/privacy-training/dataset.py check --data research/privacy-training/data/v1
python3 research/privacy-training/dataset.py export --data research/privacy-training/data/v1 --output artifacts/privacy-training/sft-v1
```

Для обеих версий фиксировать ревизию [Qwen/Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B), версию токенизатора и шаблон диалога. Сохранить `pip freeze`, `nvidia-smi`, SHA-256 манифеста и конфигурацию запуска рядом с локальными результатами. Для сборки окружения использовать поддерживаемый на ноутбуке стек CUDA, PyTorch, Unsloth и TRL. Поскольку Qwen3.5 содержит визуальный энкодер, при текстовом обучении использовать поддерживаемый текстовый путь и языковые LoRA-слои. [Рецепт Unsloth для Qwen3.5](https://unsloth.ai/docs/models/qwen3.5/fine-tune)

## Обучение

1. Снять исходный вывод Qwen на `validation` и `test-inputs.jsonl` и сохранить ответы для парного сравнения. Для выбора параметров использовать `validation`. Разбор `test` провести после выбора checkpoint.
2. Провести короткий запуск на 20 шагов оптимизатора. Настройки ниже задают отправную точку. Проверить, что вход и эталонный ответ целиком помещаются в контекст, loss конечен, адаптер сохраняется и загружается, а модель возвращает JSON. Измерить пик VRAM и время шага.
3. После технического прогона обучить один заранее заданный пилот на `train` в течение 1–2 эпох. Выбрать checkpoint по `validation`. Воспроизвести окончательные измерения на `test` при той же инструкции, разбиении текста и параметрах генерации.

| Параметр | Начальная настройка |
|---|---|
| Веса | Qwen3.5-2B, BF16 LoRA |
| Контекст | 1024 токена вместе с ответом |
| Размер батча | 1 на GPU, накопление градиента 4 |
| Адаптер | `r=16`, `lora_alpha=32`, языковые проекции |
| Скорость обучения | `1e-4`, сохранить конфигурацию планировщика |
| Контроль воспроизводимости | `seed=42`, фиксированное разбиение |
| Выходы | Локальная папка `artifacts/privacy-training/`, адаптер и конфигурация |

Экспорт совместим с диалоговым prompt-completion в `SFTTrainer`. Использовать `completion_only_loss=True` и одинаковый шаблон Qwen для обеих моделей. Сверить поддержку параметров с установленной версией TRL. [Формат и параметры TRL](https://huggingface.co/docs/trl/sft_trainer)

```python
from datasets import load_dataset

data = load_dataset("json", data_files={
    "train": "artifacts/privacy-training/sft-v1/train.jsonl",
    "validation": "artifacts/privacy-training/sft-v1/validation.jsonl",
})
train = data["train"].remove_columns("id")
validation = data["validation"].remove_columns("id")
```

GPU-обучение и экспорт адаптера в GGUF относятся к запуску на ноутбуке. Для первого сравнения можно проверить исходную модель и LoRA в одном рантайме. Повторить проверку после квантизации перед подключением GGUF к Kaponir.

## Измерение качества

Сравнить штатные детекторы, детекторы с исходной моделью и ту же связку с LoRA. Для двух модельных вариантов использовать одинаковый код применения. Текущий поиск воркера читает `candidates` со значениями, типом и уверенностью. Экспериментальный вывод `spans` требует привязки по вхождениям перед применением, чтобы публичная и приватная копии одной строки могли получить разные решения. Проверять тип, границы и присутствие в исходнике перед созданием замены. [Контракт воркера](../../docs/WORKER.md)

Отдельно измерить качество разметки и результат её применения.

- **Разметка модели** — точность и полнота точных приватных вхождений, частичные границы, пропуски, лишние находки, ошибки типа, некорректный JSON и доля `review`.
- **Выход Kaponir** — полностью скрытые `mask`-вхождения относительно всего приватного эталона, отдельно частичные и оставшиеся открытыми. Считать публичные `keep`-вхождения, затронутые маской, лишние замены и точность восстановления. Сверять содержание запроса у локального тестового получателя.

Цель пилота — не менее 95% полностью скрытых приватных вхождений на новых размеченных запросах с сохранением публичного контекста. Для синтетического `test` v1 это минимум 290 из 305 приватных вхождений. Сравнивать результаты по языку, типу, формату и группе. Частичное закрытие остаётся пропуском для расчёта полной маски. Случаи `review` учитывать отдельно от публичных.

В v0 варианты групп сгенерированы по небольшому числу шаблонов. В v1 добавлены отдельные сценарии с пустыми ответами, похожими значениями и форматами, которых мало в исходном наборе. Сравнение проверяет перенос между этими синтетическими группами. Перед оценкой на рабочем потоке нужен свежий контрольный набор по разным документам и проектам с фактически проверенной разметкой. Публичные материалы прежнего исследования годятся как фиксированная регрессия. [Исходные замеры](reports/baseline.md)

В [отчёты](reports/README.md) положить итоговый результат пары, хеши данных и весов, конфигурацию, показатели по группам, типовые ошибки и профиль ресурсов. Сырые логи, реальные значения, скачанные веса и промежуточные GPU-артефакты хранить локально в закрытом контуре.
