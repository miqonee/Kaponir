## Что изменило дообучение

**Полный поиск.** База и адаптер получили семь одинаковых запросов на одном CPU. С адаптером модель сгенерировала 2 441 токен против 5 571, а суммарное время HTTP-запросов сократилось с 7,44 до 4,63 минуты. Адаптер закрыл 15 прежних пропусков и потерял полное покрытие на 17 других позициях. Восемь из десяти дополнительных публичных потерь пришлись на справку. По основному баллу 60:30:15 база выиграла 83,85 против 81,44. С повышенным весом скорости (50:20:30) адаптер чуть впереди, 78,85 против 78,54. Обе версии побайтово восстановили 3/3 документов. [Результаты по документам и квитанции](reports/epoch2/search.md)

**Проверка готовых целей.** У базы лучший балл дал B (59,0). При одинаковом промпте C дообучение подняло число верных решений с 11/32 до 27/32, а D — с 21/32 до 26/32. Время базы в этой серии взято из исторического запуска. Состав целей и хеши запросов совпали. [Все четыре варианта, ошибки и формула балла](reports/epoch2/abcd.md)

**Допуск.** На отдельной validation-v4 новая вторая эпоха закрыла 53/57 приватных вхождений против 41/57 у прежней первой эпохи. После CSV-коррекции затронуты 25/57 публичных вхождений, из них 24 затрагивали и одни штатные детекторы. Все 71 документ восстановился. Для допуска нужны ≥55/57 приватных и ≤1/57 публичных. Отбор закончился без кандидата, независимый test-v4 остался замороженным. Штатный HTTP-прокси и исследовательская связка с ответами Qwen измерялись отдельно. [Сверка validation-v4](reports/epoch2/validation-v4.md) · [Отбор](results/v4/selection.json) · [Измерения штатного прокси](https://github.com/miqonee/Kaponir/blob/947fb2434808ed101cf5816cb50793abbf2323be/research/privacy-training/reports/native-proxy-v4.md)

В парном опыте обе версии использовали один и тот же базовый GGUF. Для epoch-2 к нему подключали отдельный адаптер LoRA в формате GGUF F32 с коэффициентом 1,0. Поисковый сценарий добавляет находки модели к детекторам и измеряет текст после применения масок. Наборы промптов, параметры запросов и ответы сохранены в [архиве поиска](reports/epoch2/search-evidence.tar.gz) и [архиве A–D](reports/epoch2/abcd-evidence.tar.gz).

Две эпохи заняли 322 шага и 48 мин 19 с на RTX 4080 Laptop. Для validation-v4 использовали промпт v3, контекст 1 024 и жадную генерацию до 256 токенов с выключенными рассуждениями. ## Проверка без модели

Из корня репозитория выполните команду с Python 3.12. Она сверяет SHA-256 двух архивов, все 60 вложенных файлов и обе опубликованные таблицы JSON с результатами внутри архивов. Для этого достаточно CPU, сеть и веса не требуются.

```sh
python3 research/privacy-training/verify_epoch2.py
```

## Как повторить поиск и проверку целей

Команды рассчитаны на Bash в Linux, Python 3.12 и Rust. Запускайте из корня `main`. Для бенчмарка возьмите опубликованный снимок `d0424ad`. На нём проверено совпадение всех 20 подготовленных запросов A–D и выгрузки детекторов поиска с архивом. Журнал исходной машины указывает другую ревизию `2c68519`, которая отсутствует в публичном Git. Для сопоставления машин сохранены хеши исполняемых файлов, входов и ответов. [Манифест поиска](reports/epoch2/search-manifest.json) · [Манифест A–D](reports/epoch2/abcd-manifest.json)

1. Подготовьте бенчмарк и соберите CLI. Это отдельная рабочая копия.

   ```sh
   git worktree add --detach ../kaponir-benchmark d0424adff53bfff18964cf61f7f5e9d2b905b421
   BENCH=$(cd ../kaponir-benchmark && pwd)
   cargo build --locked --release --manifest-path "$BENCH/Cargo.toml" --target-dir "$BENCH/target" -p kaponir-cli
   ```

2. Укажите исполняемый файл `llama-server` из Linux-релиза b12038, каталог с базовым файлом `Qwen3.5-2B-Q4_K_M.gguf` и путь к **отдельной** LoRA F32. Создавать объединённую модель для этого прогона не требуется. Веса PEFT второй эпохи опубликованы в Git LFS. Для конвертации используются `convert_lora_to_gguf.py --base <каталог конфигурации базовой Qwen> --outtype f32 --outfile <путь к LoRA.gguf> <каталог адаптера>` и ревизия llama.cpp из манифеста. [Базовый GGUF](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF/resolve/f6d5376be1edb4d416d56da11e5397a961aca8ae/Qwen3.5-2B-Q4_K_M.gguf) · [Адаптер PEFT](https://github.com/miqonee/Kaponir/tree/947fb2434808ed101cf5816cb50793abbf2323be/research/privacy-training/results/v4/full/epoch-2) · [Конвертер](https://github.com/ggml-org/llama.cpp/blob/a7a490a4905c36349f1074d3f5322291304a6dd3/convert_lora_to_gguf.py) · [llama-server b12038](https://github.com/ggml-org/llama.cpp/releases/tag/b12038)

   ```sh
   SERVER=/path/to/llama-server
   MODELS=/path/to/models
   LORA=/path/to/kaponir-privacy-v4-epoch-2.lora.gguf
   sha256sum "$SERVER" "$MODELS/Qwen3.5-2B-Q4_K_M.gguf" "$LORA"
   ```

   | Файл измеренного прогона | SHA-256 |
   | --- | --- |
   | llama-server | `3e042c4518a74fc3bdb3edb80e07922ee01d6a3455618952af23f3e546508934` |
   | Базовый GGUF | `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223` |
   | Отдельная LoRA GGUF | `48cc50e1bd06fdc68d742211d4690094597f1dcd91d86330cf44243235afc68a` |

3. Выполните две серии последовательно на одном CPU. Укажите новый каталог вывода для каждой попытки. Сценарий сам загружает параметры соответствующего профиля и проверяет активный адаптер. Для измерения всех четырёх вариантов A–D опустите `--variants C D`.

   ```bash
   RUN=research/privacy-training/compare_epoch2.py
   common=(--repo "$BENCH" --runtime "$SERVER" --model-dir "$MODELS")
   binary=(--binary "$BENCH/target/release/kaponir")
   OUT=artifacts/epoch2-comparison

   python3 "$RUN" search "${common[@]}" "${binary[@]}" --output "$OUT/search-base"
   python3 "$RUN" search "${common[@]}" "${binary[@]}" --adapter "$LORA" --output "$OUT/search-epoch2"
   python3 "$RUN" abcd "${common[@]}" --variants C D --output "$OUT/abcd-base"
   python3 "$RUN" abcd "${common[@]}" --variants C D --adapter "$LORA" --output "$OUT/abcd-epoch2"
   ```

Для поиска сравните `summary.json`, затем позиции и восстановление в `application/result.json`. Для C/D откройте `result.json` и сопоставьте решения по тем же 32 целям каждого варианта. Время в балле зависит от машины. [Сценарий сравнения](compare_epoch2.py) · [Исходная публикация парного прогона](https://github.com/miqonee/Kaponir/tree/d7a315d39c312cc7fbc1dbaca5c6bec340af055b/research/privacy-training/reports/epoch2)
