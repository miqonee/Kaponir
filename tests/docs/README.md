## Разметка

Эталон находится отдельно в [expected.json](expected.json). В модель передавайте только
файлы из `input/`, чтобы она не получила разметку и этот README вместе с заданием.

Для каждого значения указаны точный текст, `kind`, `scope` и число вхождений.
Зафиксирована следующая политика контуров:

- `personal`: пароли, токены, учётные записи, сотрудники, почта и телефоны;
- `team`: проекты, сервисы, модули, внутренние хосты/IP, пути и операционные идентификаторы;
- `global`: организации, клиенты, корпоративные домены, договорные идентификаторы и закрытые суммы.

Это эталонная политика именно данного набора. Например, конкретный внутренний хост
размечен как `HOST/team`, а корпоративный корневой домен — `DOM/global`.
Суммы включают обозначение валюты. У паролей и токенов кавычки, имена полей и слово
`Bearer` в значение не входят. Даты, проценты, количества, статусы HTTP и публичные
названия технологий остаются открытыми. Для конфигурации эталон включает корневой
домен и конкретные хосты отдельно; такие значения могут пересекаться в исходнике.

Проверка числа вхождений учитывает границы слов и регистр: `s1` не совпадает с `s10`,
а `7 500,00 ₽` не считается вхождением внутри `17 500,00 ₽`. Изменение регистра,
пробелов, валюты или выделение только части значения отражается как отличие от эталона.

## Проверка исходников

```sh
python3 scripts/check_learning_corpus.py --output artifacts/docs-corpus/validation.json
```

Проверяются состав набора, SHA256 и размер каждого файла, наличие значений, типы,
контуры, число вхождений и отрицательные примеры. У сметы дополнительно пересчитываются
все 26 строк, скидка, НДС, аванс и остаток. Итог сметы — **3 292 699,92 ₽**.
При изменении исходника пересмотрите разметку и обновите его размер/SHA256; не подгоняйте
эталон под ответы конкретной модели.

## Сравнение с обнаружением и категоризацией

Используйте отдельное тестовое пространство. Выключите автоактивацию правил и
автоматический анализ новых ходов; иначе уже выученные правила и предыдущие задания
могут повлиять на полноту следующего прогона. Передавайте документы с именами файлов
из таблицы. Дождитесь обработки всех восьми источников, включая публичный документ.

Результат обнаружения можно сохранить как JSON-массив:

```json
[
  {"file":"01-cost-estimate.md","value":"Кедровый Атлас"},
  {"file":"02-application.log","value":"Reed!62Cove#918"}
]
```

Для проверки категоризации добавьте поля `kind` и `scope`. Также принимается полный
ответ `GET /api/v1/ui/learning`: из `entries` используются `source`, `value`, `kind` и
`scope`. В ответе не должно быть находок других прогонов; API имеет лимит записей,
поэтому при больших сериях сохраняйте результаты до вытеснения их из выдачи.

```sh
python3 scripts/check_learning_corpus.py \
  --predictions /path/to/predictions.json \
  --output artifacts/docs-corpus/model-report.json
```

Отчёт разделяет:

- полноту обнаружения и точность списка найденных значений;
- ошибки типа и контура, а также находки без категоризации;
- пропуски, лишние находки и срабатывания на публичных контрольных значениях;
- значения, которых нет в исходнике, и расхождения границ выделения;
- результаты по документам и типам сущностей.

Повтор одного значения в документе считается одной находкой, повторные предсказания
с одинаковой категоризацией объединяются. Противоречивые категории для одного значения
требуют раздельных прогонов. Число вхождений в эталоне проверяет состав документа;
без позиций в предсказании оно не измеряет полноту маскирования всех вхождений.
Для документов без чувствительных значений и пустых ответов некоторые отношения
не определены и записываются как `null`.

Скрипт сравнения не запускает модель, не обращается к сети и не изменяет правила.
Синтетический набор подходит для воспроизводимых регрессий. Для оценки реальной
точности и калибровки порога 85% потребуется отдельная независимая разметка.
