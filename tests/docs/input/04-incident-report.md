# Отчёт по инциденту INC-2026-047

Уровень доступа: рабочая группа проекта Тихий Причал и владелец системы.
Автор: Марина Андреевна Леснова. Ответственный за восстановление: Олег Ильич Крылов.
Дата: 11 ноября 2026 года. Временная зона хронологии — UTC+07:00.

## Что произошло

В 09:14 после обновления cedar-api до версии 2.8.4 часть операций завершалась
ошибкой записи отчёта. Ошибка проявлялась только на узле 10.74.18.21 и была
связана с владельцем каталога /var/lib/cedar/reports. Повторное выполнение запроса
сохраняло событие в очереди, но не создавало итоговый файл. Для cedar-worker это
означало повторное чтение одной и той же записи, а не получение новых данных.

Во время диагностики оказался включён расширенный DEBUG-вывод. В локальный журнал
попали значение пароля БД Reed!62Cove#918 и ключ kpn_fixture_8sD4fP6nR2aW9mV3.
Это были два разных секрета. Адрес БД — pg01.cedar.test, технический логин — svc_cedar.
Доступ к кэшу cache01.cedar.test с адресом 10.74.18.23 отдельно не нарушался.

## Влияние

Потери исходных событий не выявлено. Из 12 контрольных запросов один получил HTTP 500,
три встретили HTTP 429 при первом обращении к шлюзу, остальные завершились с HTTP 200.
Счётчик повторных попыток не равен числу потерянных событий. Измерения 12 мс и 42 мс
относятся к отдельным строкам журнала и не являются ни паролями, ни суммами договора.

При внешней передаче лога без подготовки раскрылись бы топология стенда, техническая
учётная запись и два секрета. Полный журнал не помещали в открытый трекер: для обсуждения
оставили статусы, времена, версию и вырезку traceback без значений конфигурации.

## Хронология и принятые меры

- 09:14 — развёртывание завершилось, проверка /healthz вернула HTTP 200.
- 09:15 — подтверждена ошибка прав в каталоге /var/lib/cedar/reports.
- 09:17 — создана временная учётная запись helpdesk-demo; одноразовая фраза Cove-94!Slate-27
  была передана дежурному по закрытому каналу и тоже попала в журнал диагностики.
- 09:18 — выполнен откат до 2.8.3, владелец каталога исправлен, очередь обработана повторно.
- 09:19 — пароль сменён на Reed!63Cove#104, ключ API сменён на kpn_fixture_6jL9wS2uH7fA5cR8.
- 09:20 — временный доступ helpdesk-demo закрыт, расширенный вывод заголовков отключён.

Для проверки использовались marina-ops и batch-demo. Состояние обработки после восстановления
сверили с объектами в cedar-staging-archive. Смена ключей не должна уничтожать уже записанные
соответствия, необходимые для восстановления старых сообщений.

## Разбор причин

В поставке изменился порядок создания рабочих каталогов. Проверка запуска выполнялась
раньше, чем приложение пыталось записать первый отчёт, поэтому одного положительного
ответа /healthz оказалось недостаточно. Проверки миграций БД и загрузки данных были
успешны и к отказу записи не относились. Увеличение числа повторов лишь умножило одинаковые
сообщения об ошибке; оно не могло исправить владельца каталога.

Отдельно обнаружен дефект диагностического режима: значение authorization записывалось
полностью. Одного скрытия строки password было бы недостаточно — заголовок доступа и
ключ шлюза имели другие имена полей. Поиск должен учитывать и смысл, и расположение
значения, а не только одно название параметра.
