## Runtime, память, остановки и кеш

Среда исследования: CPU quota 2, RAM 8 GiB, диск ~7.9 GiB; llama.cpp b12038.
Runtime SHA в STATE и signature. `--no-mmproj` означает текстовый режим GGUF;
аргумент `--language-model-only` другого движка не передавался буквально.

Три разных технических случая: старые байтовые фрагменты 3201+895=4096/length;
рост отдельного RAM-архива Qwen ~2→7.7 GiB без OOM; неограниченное reasoning
до 8192 без финального JSON. Не сводить их к одному OOM. Во всех завершённых
больших основных прогонах OOM=0. Подход к памяти: `--cache-ram 0`,
`--no-cache-idle-slots`, request `cache_prompt=false`.

Main checkpoint policy v1 хеширует experiment_inference.py и evaluate_validation_schemes.py.
У Nanbeige есть пять старых технических записей до исправления кеша поиска;
их тела не сохранились и незаконченная часть была сгенерирована повторно один раз.
После исправления ответ сохраняется перед рекурсивным делением, replay не создаёт
новых физических записей. `discovery_checkpoint_initial_calls=5` отделяет legacy.
Ошибки записи checkpoint не превращаются в решения модели.

Gemma full-контроль восстановлен фоновым наблюдателем с одним сохранённым ответом.
Этот ответ не генерировался повторно. Незавершённая генерация не равна завершённому
ответу; runtime_restarts сохранены. Текущая очередь завершена.

Служебные finish-heavy/light/supervisor из evidence/session — исторические ссылки:
они содержат абсолютные `/tmp`-пути и удаление task-owned сборочных кешей для экономии
диска. Не используйте их как универсальный запускатор на другой машине.

## Работа с источниками

- `data/validation-results.json` — итоговый машинный свод, `data/validation/` — 41 archive.
- `data/COLLECTION.json` — весь захват, aliases, redactions, omissions.
- `data/experiment-index.csv` — где лежат ранние/неудачные/внешние результаты.
- `data/models.json` — семь GGUF с байтами, SHA и закреплёнными HF URL.
- `evidence/source/repository.bundle` — офлайн Git-история с кодом всех этапов.
- `reference/*.md.gz` — точные тексты прежних отчётов. Их ссылки относились к
  исходному дереву docs; для навигации используйте корневые документы пакета.
- Исторический `status=running` в старом артефакте не означает активную задачу.
  Актуальный статус — STATE и завершённые очереди.
- Старые рабочие ключи не входят в пакет. Для внешнего нового теста нужен актуальный
  локально настроенный доступ; восстановление результатов сети не требует.

Новые профили писать в новый каталог, например `artifacts/privacy-policy-phase2/<run-id>`.
Фиксировать source/runtime/model/prompt/schema/policy hashes, sampling, seed,
пулы и техническую завершённость. Не продолжать старый result.json после смены
производителя, промпта, схемы, политики или модели. Не подмешивать эталонные типы,
scope и метки в вход LLM. Исправление детекторов измерять отдельным baseline,
сохраняя прежний пул для сравнения LLM.

В этой managed-среде обычная песочница запрещала даже loopback-сокеты. Четыре
worker-теста давали PermissionError и затем все 117 прошли с разрешённым loopback.
Это не продуктовая регрессия. Новому агенту следует проверить фактическую среду,
а не переносить старые порты/PID/состояния из логов.
