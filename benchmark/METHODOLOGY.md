# Методика и границы сравнения

## Данные и единица измерения

В общем сравнении 01/02/08: 92 уникальных значения, 51 из них — суммы.
Полный синтетический корпус: восемь документов, 219 уникальных значений, 363 вхождения.
Исходники и разметка — [expected.json](data/corpus/expected.json), входные файлы
перечислены в [STATE.json](STATE.json) и [сводке](data/validation-results.json).
SHA-256 разметки: `1815af85ae5198240fac4d9aaff659d33e35779f5bc1ae621699afafc370ce92`.

Совпадение — точная строка в правильном документе. Частичное ФИО, URL вместо
hostname или строка таблицы вместо суммы не равны точному эталону. Вне эталона
включает ошибки границ. Поиск значения не равен измерению утечки после настоящего
mask/restore. Для этого нужен отдельный интеграционный тест всех вхождений.

`Business discovery` — дополнительный локальный поиск предложений для разбора,
без LLM. В основной базе объединены его предложения и сырые срабатывания
встроенных детекторов; фактически применённые маски считаются отдельно.

## Шесть основных схем

| Код в JSON | Понятное описание | Что важно при оценке |
|---|---|---|
| `detector_proposals` | Локальные предложения без LLM: встроенные детекторы + business discovery | 94 кандидата: 68 эталонных, 26 вне; фактически применено 32: 15/17 |
| `current_union` | Добавить самостоятельный поиск LLM к исходным предложениям | Исходный пул сохраняется; это кандидатный поиск |
| `point` | Проверить кандидатов исходного локального пула | Ошибочный keep отбрасывает уже найденное приватное |
| `regions` | Найти заново значения в целых записях срабатывания | Другой пул; отсутствие в нём не является успешным keep |
| `union_point` | Один проход проверки по объединённому пулу | Внутри модели тот же пул, что и для double |
| `double` | Второй независимый по входам аудит и объединение двух решений | Одна модель не даёт независимых ошибок; второй проход не видит первый ответ |

Основной профиль: CPU/2 потока/1 слот; контекст 4096, ответ 1600, резерв 64;
подсказка документа 256, политика prefix; пакет до восьми кандидатов;
до 24 разных извлечённых значений, до 256 фрагментов; temperature=0, thinking off.
У младших timeout=300 с, у больших 1200 с. Все завершённые запросы четырёх младших
основной матрицы уложились в 300 с; максимальный — 259.686 с.

Вход считается нативным токенизатором с chat template. Одинаковые лимиты не означают
одинаковый видимый текст и границы пакетов для разных токенизаторов. Таблицам
передаются заголовки, логам — запись с продолжениями. Исходный тип/вероятность
детектора не передаются проверяющей LLM. ID непрозрачные, значения не переписываются.

## Контракт проверки

Ответ: ID, mask/keep/review, тип, scope, цитата evidence и reason.
Reason до 120 символов, evidence до 160. Проверяются состав/уникальность ID,
длины, типы, точное наличие цитаты и совместимость формата значения с типом.
Невалидный ответ оставляет review. Структурная валидность не гарантирует верности
приватности. Scope: personal для людей/аккаунтов/контактов/credentials, team для
внутренних проектов/сервисов/хостов/путей, global для компаний/клиентов/коммерческих
условий. Это политика бенчмарка; выбор реального проекта не измерялся.

В основном пуле десять защищённых предложений: семь эталонных credentials и три
вне эталона. Их нельзя удалить решением LLM. Нельзя считать эти подтверждения
успехом модели. Candidate-only флаги confirmed и начальный scope — служебные
поля пула, а не измеренное решение о приватности.

Два валидных keep отклоняют значение. Два mask подтверждают его при согласии
типа и scope. Остальное — review. «Независимость» здесь относится к входам,
а не к гарантии независимых ошибок модели.

## Контроли и другие слои

| Серия | Данные | Отличия от основной матрицы |
|---|---|---|
| Правильные границы | 32 кандидата: 16 приватных, 16 публичных | Защита credentials отключена, типы и метки — только оценщику |
| `record` / `document` | Те же 32 | Запись + короткая подсказка / целый документ один раз на пакет |
| Полный поиск | Те же три документа | Контекст 16384, выход 4096, retry до 8192, до 128 кандидатов |
| `bounded` | Тот же вход | Thinking on с бюджетом reasoning 2048 |
| `off` | Тот же вход | Thinking off |
| `on` | Тот же вход | Без ограничения reasoning; пустое усечение останавливает вариант, остаток не оценивается |
| Один кандидат | Те же 32 | Общий контракт сохранён, batch_size=1; чистый бинарный вопрос не изолирован |
| 20 диагностических проб | Отдельная фикстура | Настройка/диагностика, не новая документная матрица |
| 12 ранних проб | Отдельная калибровка | У части смысловые ID и старая политика scope; результаты исторические |
| Деривация регионального пула | Сохранённые списки | Объединение без новых вызовов; не прогон применения правил |

Рекомендованный sampling полных профилей: Nanbeige temperature=.6/top_k=20,
Granite 1/40, Gemma 1/64; top_p=.95, min_p=0, seed=42. Младший общий профиль — greedy.
Все фактические параметры и контроли — в signature архивов. Один seed не доказывает
устойчивость. `prompt` меняет и инструкцию JSON, и способ ограничения формата;
это не изолированный эффект одного grammar-флага.

## Сопоставимость и неполные результаты

- Все семь основных прогонов имеют одинаковые документы, эталон, исходный пул
  и хеши инструкций. Токенные бюджеты одинаковы.
- Nanbeige — prompt-JSON; остальные в основной матрице — JSON Schema.
  При prompt лимит 24 — инструкция/порог дробления, при grammar — жёсткий лимит массива.
- Gemma — QAT Q4_0; остальные Q4_K_M. Это не изоляция влияния числа параметров.
- `status=completed` означает завершение протокола. Отдельные методы могут быть
  технически неполными: смотрите errors, complete_documents, failed_batches,
  invalid_decisions, attempted_cases и quality_is_lower_bound_if_incomplete.
- Таймаут не является обычным семантическим пропуском; невыданный ответ не получает
  нулевую точность. STOP тоже не доказывает правильный JSON: это воспроизведено.
- Request errors и stage errors могут относиться к одному запросу; их нельзя складывать.
- Старый RAM-архив и параллельные сборки искажали wall time; рейтинга скорости нет.
- На пяти отложенных документах проверен выбранный ранее Qwen2, а не все семь моделей.
- Внешний 192/219 использовал другой профиль и слой приложения; прямого рейтинга
  против 92-значной матрицы по этому числу нет.
- S1 и пользовательские правила выключены; результаты не меняли Vault и обучение.
